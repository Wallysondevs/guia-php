PHP Mensagens de Erro

Quando algo dá errado, o PHP escreve uma mensagem em inglês com o tipo do problema, o texto, o arquivo e a linha. Esta página junta as mensagens que você mais vai encontrar, cada uma com o código que a provoca, o que ela quer dizer, como consertar e a aula onde o assunto é explicado. Todas foram provocadas de verdade no PHP 8.5, na máquina da Ana. Para aprender a ler erros com calma, veja Lendo Erros do PHP e Tipos de Erro.

Como usar esta página
  • Copie o começo da mensagem que apareceu para você (por exemplo, Undefined array key) e procure aqui com Ctrl+F.
  • As mensagens foram geradas por arquivos pequenos na pasta ~/erros da Ana (e08.php, f05.php…). No seu computador, o caminho e o número da linha serão outros; o texto é o mesmo.
  • Nas tabelas aparece só a primeira linha de cada erro. Os erros "Uncaught" também trazem um Stack trace, explicado logo abaixo.

Regra de ouro

Leia a primeira mensagem primeiro. Um erro costuma causar outros logo depois (um arquivo que não abriu vira um false, que estoura na linha seguinte). Conserte o primeiro e rode de novo.

No terminal × no navegador

A mesma mensagem aparece de jeitos diferentes conforme o lugar e a configuração (php.ini):

OndeComo aparece
Terminal (php arquivo.php)Warning: … na saída normal, com uma linha em branco antes. Se o php.ini tiver log_errors=On (comum no PHP das distribuições Linux), aparece também PHP Warning: … na saída de erro.
Navegador (php -S, Apache…)Em HTML: <b>Warning</b> em negrito, no meio da página, se display_errors estiver ligado (desenvolvimento).
Log do servidorO php -S escreve os erros fatais no terminal onde ele está rodando, junto com cada requisição.
Produção (site no ar)display_errors=Off: o visitante não vê nada (só uma página em branco ou um erro 500); a mensagem vai para o arquivo de log. Veja Depurar.

Com log_errors ligado, a mensagem sai duas vezes. A primeira (PHP Warning: …, com dois espaços) é o log, na saída de erro; a segunda é a exibição:

Parse error (sintaxe)

O PHP lê o arquivo inteiro antes de rodar. Se a "gramática" estiver errada, nada é executado. A linha apontada é onde o PHP percebeu o problema, que muitas vezes está na linha anterior. Aula: Sintaxe.

Missão: zero avisos

O programa da seção Os níveis tem três problemas, um em cada linha que gera mensagem. Rode, leia as mensagens de cima para baixo e conserte uma por vez.

Missão: faça o programa mostrar Aluna: Ana, Notas: 7, 8 e Média: 7.5 sem nenhum Warning ou erro. Dicas: a chave tem outro nome; um array não vira texto sozinho (implode); quantas notas há? (count).

<?php
$aluno = ["nome" => "Ana", "notas" => [7, 8]];
echo "Aluna: " . $aluno["Nome"] . "\n";
echo "Notas: " . $aluno["notas"] . "\n";
$quantidade = 0;
echo "Média: " . array_sum($aluno["notas"]) / $quantidade . "\n";

<?php
$aluno = ["nome" => "Ana", "notas" => [7, 8]];
echo "Aluna: " . $aluno["nome"] . "\n";
echo "Notas: " . implode(", ", $aluno["notas"]) . "\n";
$quantidade = count($aluno["notas"]);
echo "Média: " . array_sum($aluno["notas"]) / $quantidade . "\n";

Resumo

  • Toda mensagem tem nível, texto, arquivo e linha. "Uncaught X" = exceção X não tratada; o Stack trace mostra o caminho até ela.
  • Parse error: nada roda; olhe também a linha anterior. Fatal error: para. Warning/Notice: continua com valor errado. Deprecated: funciona, mas vai mudar.
  • Os campeões: Undefined variable, Undefined array key, … on null, Call to undefined function, headers already sent, no such table.
  • Conserte a primeira mensagem e rode de novo; muitas das seguintes somem junto.
  • php -l confere a sintaxe; no site no ar, os erros vão para o log, não para a tela (Depurar).
