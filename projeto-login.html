PHP Projeto Login com Sessão

Quase todo site tem uma parte que só aparece para quem entrou com e-mail e senha. Neste projeto você monta essa parte do zero: a página de cadastro, a de login, um painel que só abre para quem entrou e o botão de sair. E, como login é o alvo preferido de quem ataca sites, cada etapa fecha uma porta: senha guardada com password_hash, sessão renovada no login e formulários protegidos com token CSRF. Os ataques são mostrados de verdade, com o curl.

Você vai aprender
  • Organizar um projeto em vários arquivos com um comum.php incluído em todas as páginas.
  • Cadastrar usuários num banco SQLite, guardando só o hash da senha (password_hash).
  • Conferir a senha no login com password_verify e lembrar quem entrou com $_SESSION.
  • Proteger uma página (área restrita) e fazer o logout que apaga a sessão e o cookie.
  • Por que chamar session_regenerate_id(true) no login (fixação de sessão, demonstrada).
  • O que é CSRF e como um token escondido nos formulários impede o ataque.

    Abre a sessão: lê o cookie PHPSESSID (ou cria um novo) e enche o array $_SESSION. Precisa vir antes de qualquer saída, como o header().
    'cookie_httponly' => true

    Trancar uma página é simples: logo no começo, antes de mostrar qualquer coisa, pergunte "tem alguém logado?". Se não tiver, mande para o login e pare.

    O exit dentro do redirecionar() é o que realmente tranca: sem ele, o PHP mandaria o cabeçalho de redirecionamento e continuaria gerando o painel. Um navegador obedeceria e mudaria de página, mas o curl (ou qualquer robô) leria o conteúdo secreto na resposta.

    $ curl -si localhost:8000/painel.php | grep -E 'HTTP|Location'
HTTP/1.1 303 See Other
Location: login.php
$ curl -sL localhost:8000/painel.php | grep h1
<h1>Entrar</h1>                « seguindo o redirecionamento, cai no login

    Toda página restrita repete essas três linhas. Num projeto maior, elas viram uma função no comum.php, e é isso que a missão pede.

    Missão: crie no comum.php a função exigir_login(): array, que redireciona para o login quando não há usuário e, se houver, devolve $_SESSION['usuario']. No painel, troque o if e a linha seguinte por $usuario = exigir_login();. A caixa abre o painel sem login: o resultado deve ser a página Entrar.

  4. Etapa 4 · Sair (logout)

    Sair é desfazer o login: esvaziar a sessão, apagar o cookie do navegador e destruir a "gaveta" no servidor. Por enquanto, um link simples no painel leva ao sair.php:

    <p><a href="sair.php">Sair</a></p>
    <?php
require __DIR__ . '/comum.php';

$_SESSION = [];
$p = session_get_cookie_params();
setcookie(session_name(), '', time() - 3600, $p['path'], $p['domain'], $p['secure'], $p['httponly']);
session_destroy();

redirecionar('login.php?saiu=1');
    $_SESSION = [];
    Esvazia os dados da sessão (nesta requisição e no que será gravado).
    session_get_cookie_params()
    Lê como o cookie da sessão foi criado (caminho, domínio…). O cookie só é apagado se for "o mesmo".
    setcookie(session_name(), '', time() - 3600, …)
    Manda um cookie PHPSESSID vazio com validade no passado: o navegador entende "apague".
    session_destroy()
    Apaga o arquivo da sessão no servidor.
    $ curl -s -c jar.txt -b jar.txt -d 'email=ana@exemplo.com&senha=cafe-com-pao' -L localhost:8000/login.php | grep -E 'h1|Sair'
<h1>Olá, Ana!</h1>
<p><a href="sair.php">Sair</a></p>
$ grep -c PHPSESSID jar.txt
1
$ curl -si -c jar.txt -b jar.txt localhost:8000/sair.php | grep -E 'HTTP|Location|Set-Cookie'
HTTP/1.1 303 See Other
Set-Cookie: PHPSESSID=deleted; expires=Thu, 01 Jan 1970 00:00:01 GMT; Max-Age=0; path=/; HttpOnly
Location: login.php?saiu=1
$ grep -c PHPSESSID jar.txt
0                                « o cookie sumiu do pote

    O Set-Cookie: PHPSESSID=deleted; expires=Thu, 01 Jan 1970… é o pedido de "apague este cookie" (o PHP escreve deleted e uma data de 1970). Depois disso, o painel volta a mandar para o login.

Deslogar é inofensivo, mas imagine se o link fosse "apagar minha conta". Ações que mudam algo devem ser POST com token: é a etapa 6.

    Missão: conte as visitas ao painel na sessão: $_SESSION['visitas'] = ($_SESSION['visitas'] ?? 0) + 1; e mostre Visitas nesta sessão: N. Depois, na aba Resultado, recarregue o painel algumas vezes, clique em Sair, entre de novo (ana@exemplo.com / cafe-com-pao) e veja o contador recomeçar do 1.

  5. Etapa 5 · session_regenerate_id: um crachá novo a cada login

    O sistema funciona, mas tem um furo clássico chamado fixação de sessão. A ideia do ataque: o atacante escolhe um número de sessão, dá um jeito de a vítima usar esse número (um link preparado, um computador compartilhado) e espera ela fazer login. Como o número não muda no login, o atacante, que sabe o número, entra junto.

    No laboratório, com a versão da etapa 4, o "atacante" inventou o número idescolhidopelatacante. A Ana faz login usando esse cookie (primeiro comando); depois o atacante usa o mesmo cookie (segundo comando):

    $ curl -si -b 'PHPSESSID=idescolhidopelatacante' -d 'email=ana@exemplo.com&senha=cafe-com-pao' localhost:8000/login.php | grep -E 'HTTP|Location|Set-Cookie'
HTTP/1.1 303 See Other
Location: painel.php                         « nenhum cookie novo: o número continua o mesmo
$ curl -s -b 'PHPSESSID=idescolhidopelatacante' localhost:8000/painel.php | grep h1
<h1>Olá, Ana!</h1>                           « o atacante está dentro da conta da Ana

    A correção é uma linha no login.php, logo depois de conferir a senha:

        if ($usuario && password_verify($senha, $usuario['senha_hash'])) {
        session_regenerate_id(true);
        $_SESSION['usuario'] = ['id' => $usuario['id'], 'nome' => $usuario['nome']];
        redirecionar('painel.php');
    }
    session_regenerate_id
    "Gerar de novo o identificador da sessão": troca o número, mantendo os dados, e manda o cookie novo ao navegador.
    (true)
    Apaga a sessão antiga no servidor. Sem o true, o número velho continuaria valendo por um tempo.
    $ curl -si -b 'PHPSESSID=idescolhidopelatacante' -d 'email=ana@exemplo.com&senha=cafe-com-pao' localhost:8000/login.php | grep -E 'HTTP|Location|Set-Cookie'
HTTP/1.1 303 See Other
Set-Cookie: PHPSESSID=11ef8e1494f2daf925a5c6a3673fd61e; path=/; HttpOnly; SameSite=Lax      « crachá novo para a Ana
Location: painel.php
$ curl -si -b 'PHPSESSID=idescolhidopelatacante' localhost:8000/painel.php | grep -E 'HTTP|Location'
HTTP/1.1 303 See Other
Location: login.php                          « o número do atacante não vale mais nada

    Regra para levar: sempre que o nível de acesso muda (login, troca de senha, virar administrador), chame session_regenerate_id(true).

  6. Etapa 6 · Token CSRF nos formulários

    CSRF (Cross-Site Request Forgery, "falsificação de pedido entre sites") é quando outro site faz o navegador da vítima enviar um formulário para o seu site. O navegador manda junto o cookie da sessão, e o seu site acha que foi a própria pessoa. A defesa: cada formulário leva um número secreto (o token) que só o seu site conhece, e todo POST sem o número certo é recusado.

    Duas funções novas no comum.php:

    function token_csrf(): string
{
    if (empty($_SESSION['csrf'])) {
        $_SESSION['csrf'] = bin2hex(random_bytes(32));
    }
    return $_SESSION['csrf'];
}

function conferir_csrf(): void
{
    $enviado = $_POST['csrf'] ?? '';
    if (!is_string($enviado) || !hash_equals(token_csrf(), $enviado)) {
        http_response_code(403);
        exit('Formulário expirado ou inválido. Volte, recarregue a página e tente de novo.');
    }
}
    TrechoO que faz
    bin2hex(random_bytes(32))32 bytes aleatórios, próprios para segurança, escritos como 64 letras e números. Impossível de adivinhar.
    $_SESSION['csrf']O token fica guardado na sessão: um por pessoa, criado na primeira vez que é pedido.
    hash_equals(a, b)Compara dois segredos levando sempre o mesmo tempo. Um === comum para no primeiro caractere diferente, e a diferença de tempo pode ajudar um atacante a descobrir o token aos poucos.
    http_response_code(403)Responde "403 Forbidden" (proibido).

    Todo formulário ganha um campo escondido com o token, e todo arquivo que recebe POST chama conferir_csrf() antes de fazer qualquer coisa:

  <input type="hidden" name="csrf" value="<?= token_csrf() ?>">
  ...

    conferir_csrf();
    ...

Quando dá errado

Warning: session_start(): Session cannot be started after headers have already been sent

Uma página com HTML antes do require do comum.php:

$ curl -s localhost:8000/t-sessao.php
<p>Bem-vinda!</p>

O que significa: a sessão usa um cookie, e cookies são cabeçalhos; depois que a página começou a sair, não dá mais. O resultado é pior que o aviso: $_SESSION fica vazio e ninguém consegue ficar logado. Como consertar: o require __DIR__ . '/comum.php'; deve ser a primeira linha de toda página, sem nada (nem espaço) antes do <?php.

Fatal error: Cannot redeclare function e() 
$ curl -s localhost:8000/t-dupla.php
<br />
<b>Fatal error</b>:  Cannot redeclare function e() (previously declared in /home/ana/login/comum.php:10) in <b>/home/ana/login/comum.php</b> on line <b>10</b><br />

O comum.php foi incluído duas vezes (por exemplo, uma página que inclui o comum.php e também outro arquivo que o inclui de novo), e uma função não pode ser criada duas vezes. Como consertar: use require_once, que ignora a segunda inclusão (veja include e require).

O login nunca funciona, mesmo com a senha certa

Causas comuns: comparar a senha com o hash usando == ou gerar um hash novo e comparar (password_hash($senha) === $hash), que é sempre falso por causa do sal; ou a coluna do banco curta demais e o hash cortado. Use sempre password_verify($senha, $hash) e uma coluna TEXT (ou VARCHAR(255) no MySQL).

Logado numa aba, deslogado em outra (ou o login "não pega")

O cookie da sessão não está voltando. No curl, faltou o -b jar.txt. No navegador, confira se você usa sempre o mesmo endereço (localhost e 127.0.0.1 são "sites" diferentes para os cookies) e se nenhuma página chama session_start() depois de imprimir algo.

function redirecionar(string $endereco): never
{
    header('Location: ' . $endereco, true, 303);
    exit;
}

function token_csrf(): string
{
    if (empty($_SESSION['csrf'])) {
        $_SESSION['csrf'] = bin2hex(random_bytes(32));
    }
    return $_SESSION['csrf'];
}

function conferir_csrf(): void
{
    $enviado = $_POST['csrf'] ?? '';
    if (!is_string($enviado) || !hash_equals(token_csrf(), $enviado)) {
        http_response_code(403);
        exit('Formulário expirado ou inválido. Volte, recarregue a página e tente de novo.');
    }
}

Resumo

  • Senha nunca vai para o banco: password_hash($senha, PASSWORD_DEFAULT) no cadastro, password_verify($senha, $hash) no login.
  • A sessão (session_start + $_SESSION) lembra quem entrou; o navegador só guarda o cookie PHPSESSID. Use cookie_httponly e cookie_samesite.
  • Área restrita: no topo da página, sem usuário na sessão, redirecione e pare (exit).
  • Logout: $_SESSION = [], apagar o cookie e session_destroy(); feito por POST com token.
  • No login, session_regenerate_id(true) contra fixação de sessão.
  • Todo formulário leva um token CSRF escondido; todo POST confere com hash_equals antes de agir.
  • Todo SQL com valores vindos de fora usa prepare + execute.
