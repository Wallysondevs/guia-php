Projeto Mini Blog

A Ana quer um blog para contar o que está aprendendo (e guardar a receita do pão de queijo da vó). Neste projeto você vai construí-lo do zero: os posts ficam num banco SQLite, a página inicial lista os mais recentes, cada post tem a sua página, um formulário publica posts novos, e todas as páginas compartilham o mesmo cabeçalho e rodapé. São várias páginas PHP trabalhando juntas, como num site de verdade.

Você vai praticar
  • Guardar e ler dados com PDO e prepared statements no SQLite.
  • Repartir o site em arquivos com include e require (cabeçalho, rodapé, funções).
  • Mostrar dados com segurança com htmlspecialchars (XSS).
  • Receber um formulário, validar e redirecionar.
  • Ler parâmetros da URL com $_GET e dividir a lista em páginas (LIMIT/OFFSET).

Antes de começar

Você vai precisar de PHP dentro do HTML, foreach, funções e do básico de banco de dados (o projeto Tarefas com SQLite é um bom aquecimento). Crie a pasta e deixe o servidor rodando num terminal; os curl vão em outro:

$ mkdir blog
$ cd blog
$ php -S localhost:8000

Com o servidor ligado, abra http://localhost:8000/ no navegador para ver cada etapa de verdade.

Etapa 1 · O banco e a primeira lista

O banco.php abre (ou cria) o arquivo blog.sqlite. Na primeira vez, cria a tabela posts e grava 5 posts de exemplo, para o blog não começar vazio:

<?php
$arquivo = __DIR__ . "/blog.sqlite";
$novo = !file_exists($arquivo);

$pdo = new PDO("sqlite:$arquivo");
$pdo->setAttribute(PDO::ATTR_DEFAULT_FETCH_MODE, PDO::FETCH_ASSOC);

if ($novo) {
    $pdo->exec("CREATE TABLE posts (
        id        INTEGER PRIMARY KEY AUTOINCREMENT,
        titulo    TEXT NOT NULL,
        conteudo  TEXT NOT NULL,
        criado_em TEXT NOT NULL
    )");
    $exemplos = [
        ["Olá, mundo!", "Este é o primeiro post do meu blog.\nAqui vou contar o que estou aprendendo.", "2026-10-01 09:00:00"],
        ["Pão de queijo da vó", "Ingredientes: polvilho, queijo, ovos, leite e óleo.\nAsse por 25 minutos a 180 graus.", "2026-10-03 18:30:00"],
        ["Aprendendo PHP: variáveis", "Variáveis começam com cifrão, como \$nome.\nO PHP descobre o tipo sozinho.", "2026-10-06 20:15:00"],
        ["Arrays são listas", "Um array guarda vários valores numa variável só.\nCom foreach dá para percorrer todos.", "2026-10-09 21:00:00"],
        ["Meu blog agora tem banco de dados", "Os posts agora ficam num arquivo SQLite.\nO PHP lê com PDO e prepared statements.", "2026-10-12 10:45:00"],
    ];
    $st = $pdo->prepare("INSERT INTO posts (titulo, conteudo, criado_em) VALUES (?, ?, ?)");
    foreach ($exemplos as $post) {
        $st->execute($post);
    }
}

return $pdo;
TrechoO que faz
$novo = !file_exists($arquivo);Guarda se o banco ainda não existia (ao conectar, o SQLite cria o arquivo vazio).
PDO::FETCH_ASSOCCada linha vem como array associativo: $post["titulo"].
id INTEGER PRIMARY KEY AUTOINCREMENTUm número único para cada post, escolhido pelo banco.
criado_em TEXTA data no formato 2026-10-12 10:45:00 (ano primeiro). Nesse formato, ordem alfabética = ordem de data, e o ORDER BY funciona.
$st = $pdo->prepare(…); foreach (…) $st->execute($post);Um prepared statement preparado uma vez e executado 5 vezes, uma por post. Os ? recebem os valores do array, na ordem.
"…\n…" e \$nomeEntre aspas duplas, \n é uma quebra de linha e \$ é um cifrão de verdade (sem \, o PHP procuraria a variável $nome; veja Interpolação).
return $pdo;Quem fizer $pdo = require __DIR__ . "/banco.php"; recebe a conexão.

Etapa 2 · Cabeçalho e rodapé com include

Um blog tem várias páginas (início, post, novo post) com o mesmo topo e o mesmo rodapé. Copiar esse HTML em cada arquivo seria um convite ao erro: mudou o menu, tem de mudar em todos. A solução é pôr cada pedaço repetido num arquivo e incluí-lo. Primeiro, as funções que todas as páginas usam:

<?php
date_default_timezone_set("America/Sao_Paulo");   // horário de Brasília em date()

// Escapa um texto para mostrar no HTML (contra XSS)
function e(?string $texto): string
{
    return htmlspecialchars($texto ?? "", ENT_QUOTES);
}

// "2026-10-12 10:45:00" -> "12/10/2026"
function dataBr(string $iso): string
{
    return date("d/m/Y", strtotime($iso));
}

// Os primeiros caracteres do texto, com "…" se foi cortado
function resumo(string $texto, int $tamanho = 60): string
{
    return mb_strimwidth($texto, 0, $tamanho, "…");
}
FunçãoPara quê
e(?string $texto)Um apelido curto para htmlspecialchars, que vamos escrever dezenas de vezes. ENT_QUOTES escapa também as aspas (importante dentro de value="…"). O ?string aceita null, tratado como texto vazio.
dataBr(string $iso)"2026-10-12 10:45:00" → "12/10/2026".
resumo(string $texto, int $tamanho = 60)Os primeiros 60 caracteres, com … no fim, para a lista. mb_strimwidth conta letras, não bytes, e não corta um ç no meio (referência).
date_default_timezone_set("America/Sao_Paulo")Sem isso, o date() usa o fuso UTC (3 horas à frente de Brasília) e um post das 22h sairia com a data do dia seguinte.

Resumo

  • Um site é um conjunto de páginas PHP que compartilham arquivos: require para o indispensável (banco, funções), include para pedaços de HTML (cabeçalho, rodapé), sempre com __DIR__.
  • Arquivos incluídos enxergam as variáveis de quem os inclui ($titulo): combine os nomes.
  • Banco: query sem dados do visitante; prepare + execute/bindValue com eles. fetch() pode dar false: responda 404.
  • Saída: htmlspecialchars em tudo que veio do banco ou do visitante; nl2br depois dele.
  • Formulário: o mesmo arquivo mostra (GET) e processa (POST); junte os erros num array; depois de gravar, header("Location: …") + exit.
  • Paginação: COUNT(*), ceil, prender a página entre 1 e o total, LIMIT ? OFFSET ? com PDO::PARAM_INT.
