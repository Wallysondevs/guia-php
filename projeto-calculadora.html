PHP Projeto Calculadora Web

O primeiro projeto é uma calculadora que funciona no navegador: dois campos para os números, uma lista com as quatro operações e um botão Calcular. É pequeno, mas tem tudo o que um sistema web de verdade tem: um formulário, o PHP lendo o que chegou, a decisão sobre o que fazer, a checagem do que o usuário digitou e uma resposta bem apresentada.

Você vai aprender
  • Montar uma página que mostra um formulário e também processa o envio dele (o mesmo arquivo faz as duas coisas).
  • Saber se a página foi aberta normalmente (GET) ou enviada pelo botão (POST).
  • Escolher a conta com match e entender o erro UnhandledMatchError.
  • Validar números com is_numeric, aceitar vírgula e impedir a divisão por zero.
  • Mostrar o resultado no jeito brasileiro (1.234,50) com number_format.
  • Manter o que o usuário digitou nos campos depois de enviar, sem abrir brecha de segurança.

    TrechoO que faz
    <form method="post">Quando o botão for clicado, o navegador envia os campos com o método POST (eles vão "dentro" da requisição, não na barra de endereço). Sem action, o formulário é enviado para a mesma página: o próprio index.php vai receber os dados.
    name="a", name="b"O name é o nome com que o campo chega ao PHP. Sem name, o campo nem é enviado.
    <select name="op">A lista de operações. O que chega ao PHP é o value da opção escolhida (somar, dividir…), não o símbolo que aparece na tela.
    <button>Calcular</button>Um botão dentro de um formulário envia o formulário.
    <?= date('d/m/Y') ?>O único PHP da etapa: escreve a data de hoje. Se você vir 16/10/2026 (ou a sua data), o PHP está funcionando; se vir o código <?= na página, você abriu o arquivo direto, sem servidor.
    Por que value="dividir" e não value="/"?

    Símbolos como + e / têm significado especial em endereços e formulários (o +, por exemplo, vira espaço). Palavras simples chegam sempre iguais. O símbolo bonito fica só no texto da opção.

    Com o servidor rodando, o curl mostra o final da página que o navegador recebe:

</form>

</html>

    O começo do arquivo (novo):

$b  = $_POST['b']  ?? '';

?>
<!DOCTYPE html>
...

    E, logo depois do </form> (novo):

    <?php if ($_SERVER['REQUEST_METHOD'] === 'POST'): ?>
  <p>Recebi: a = "<?= htmlspecialchars($a) ?>", b = "<?= htmlspecialchars($b) ?>", operação = "<?= htmlspecialchars($op) ?>"</p>
<?php endif; ?>

    O arquivo inteiro desta etapa está na caixa "Experimente" logo abaixo.

    $a
    A variável que vai guardar o primeiro número.
    =
    Recebe o valor da direita.
    $_POST['a']
    O campo name="a" enviado por POST. $_POST é um array associativo que o PHP enche sozinho a cada envio.
    ??
    "Se não existir, use…". Quando a página é aberta pela primeira vez, ninguém enviou nada e $_POST['a'] não existe.
    ''
    O valor padrão: texto vazio. Para a operação, o padrão é 'somar'.

    No fim da página, um if no estilo "dois-pontos" (if (…): … endif;, mais fácil de ler no meio do HTML) só mostra a linha "Recebi" quando a página chegou por POST, isto é, quando o botão foi clicado. $_SERVER['REQUEST_METHOD'] diz qual foi o método: GET quando você digita o endereço ou segue um link, POST quando um formulário method="post" é enviado.

    Sempre htmlspecialchars ao mostrar o que o usuário digitou

    Os valores vêm de fora: qualquer pessoa pode digitar <script> no campo. O htmlspecialchars troca <, >, & e as aspas pelas versões "inofensivas" (&lt;…), e o navegador mostra o texto em vez de executá-lo. A aula Escapar a Saída (XSS) mostra o ataque que isso evita.

  <p>Recebi: a = "10", b = "4", operação = "dividir"</p>
</body>
</html>
$ curl -s -d 'a=abc&b=2&op=somar' localhost:8000/ | tail -3
  <p>Recebi: a = "abc", b = "2", operação = "somar"</p>      « o PHP aceita qualquer texto
</body>
</html>

  3. Etapa 3 · Fazer a conta com match

    Hora de calcular. Os textos viram números com (float) e o match escolhe a conta pela operação:

    <?php
$a  = $_POST['a']  ?? '';
$b  = $_POST['b']  ?? '';
$op = $_POST['op'] ?? 'somar';
$resultado = null;

if ($_SERVER['REQUEST_METHOD'] === 'POST') {
    $x = (float) $a;
    $y = (float) $b;
    $resultado = match ($op) {
        'somar'       => $x + $y,
        'subtrair'    => $x - $y,
        'multiplicar' => $x * $y,
        'dividir'     => $x / $y,
    };
}
?>
...
<?php if ($resultado !== null): ?>
  <p class="resultado">Resultado: <?= $resultado ?></p>
<?php endif; ?>

    A linha "Recebi" da etapa 2 saiu: no lugar dela, o resultado. Ele só aparece quando existe (!== null).

    $resultado =
    O valor que o match devolver vai para $resultado. Antes do envio, ele fica null ("ainda não calculei").
    match ($op)
    Compara $op com cada "braço", usando === (valor e tipo iguais).
    'somar' => $x + $y,
    Um braço: se $op for 'somar', o resultado é $x + $y.
    };
    O match é uma expressão: devolve um valor, por isso termina com ; depois da chave.

    Por que match e não switch? Porque aqui queremos um valor para cada operação, sem precisar de break e sem o risco de "cair" no caso de baixo. A comparação entre os dois está na aula match.

    $ curl -s -d 'a=10&b=4&op=dividir' localhost:8000/ | tail -3
  <p class="resultado">Resultado: 2.5</p>
</body>
</html>

    Funciona! Mas esta versão é ingênua: ela confia no usuário. Veja o que acontece com três envios "maldosos":

  4. Etapa 4 · Validar antes de calcular

    A regra de ouro de todo formulário: primeiro confira, depois use. Vamos guardar os problemas encontrados numa lista $erros e só calcular se ela terminar vazia.

    O bloco do topo fica assim:

    <?php
$a  = trim($_POST['a'] ?? '');
$b  = trim($_POST['b'] ?? '');
$op = $_POST['op'] ?? 'somar';
$erros = [];
$resultado = null;

if ($_SERVER['REQUEST_METHOD'] === 'POST') {
    // aceita vírgula como separador decimal: "2,5" vira "2.5"
    $a = str_replace(',', '.', $a);
    $b = str_replace(',', '.', $b);

    if (!is_numeric($a)) {
        $erros[] = 'O primeiro número não é válido.';
    }
    if (!is_numeric($b)) {
        $erros[] = 'O segundo número não é válido.';
    }
    if (!in_array($op, ['somar', 'subtrair', 'multiplicar', 'dividir'], true)) {
        $erros[] = 'Operação desconhecida.';
    }
    if (!$erros && $op === 'dividir' && (float) $b == 0) {
        $erros[] = 'Não dá para dividir por zero.';
    }

    if (!$erros) {
        // ... o mesmo match da etapa 3 ...
    }
}
?>

    E, antes do resultado, as mensagens de erro:

    <?php foreach ($erros as $erro): ?>
  <p class="erro"><?= htmlspecialchars($erro) ?></p>
<?php endforeach; ?>
    LinhaO que faz
    trim($_POST['a'] ?? '')Tira espaços das pontas: " 10 " vira "10". Quem cola um número de outro lugar costuma trazer espaços junto.
    $erros = [];Começa a lista de problemas vazia.
    str_replace(',', '.', $a)No Brasil, escrevemos 2,5; o PHP só entende 2.5. Trocamos a vírgula pelo ponto antes de validar.
    !is_numeric($a)is_numeric ("é numérico?") responde true para textos como "10", "2.5", "-8" e "1e3", e false para "abc", "" e "2,5". O ! inverte: "se não for número…".
    $erros[] = '…';Acrescenta uma mensagem no fim da lista.
    in_array($op, [...], true)A operação está na lista das permitidas? O true faz a comparação estrita (tipo e valor).
    !$erros && $op === 'dividir' && (float) $b == 0Só se os números já estiverem bons: dividir por zero vira uma mensagem amigável, não um Fatal error. Uma lista vazia vale false, então !$erros quer dizer "nenhum erro até agora".
    foreach ($erros as $erro)Mostra cada mensagem num parágrafo (com htmlspecialchars, por hábito: amanhã a mensagem pode incluir algo que o usuário digitou).

    Os três envios que derrubavam ou enganavam a calculadora agora recebem uma resposta clara. Juntar todos os erros numa lista, em vez de parar no primeiro, é mais gentil com o usuário: ele corrige tudo de uma vez. Mais formas de validar estão em Validar Dados.

    Missão: "não é válido" é uma mensagem estranha para um campo que ficou vazio. Mude a validação: se $a === '', a mensagem deve ser Preencha o primeiro número.; senão, se não for numérico, continua "não é válido" (use if … elseif). Faça o mesmo para o $b.

    <?php

$b  = trim($_POST['b'] ?? '');
$op = $_POST['op'] ?? 'somar';

$resultado = null;

    // aceita vírgula como separador decimal: "2,5" vira "2.5"
    $a = str_replace(',', '.', $a);
    $b = str_replace(',', '.', $b);

    if (!is_numeric($a)) {
        $erros[] = 'O primeiro número não é válido.';
    }
    if (!is_numeric($b)) {
        $erros[] = 'O segundo número não é válido.';
    }
    if (!in_array($op, ['somar', 'subtrair', 'multiplicar', 'dividir'], true)) {
        $erros[] = 'Operação desconhecida.';
    }
    if (!$erros && $op === 'dividir' && (float) $b == 0) {
        $erros[] = 'Não dá para dividir por zero.';
    }

    if (!$erros) {
        $x = (float) $a;
        $y = (float) $b;
        $resultado = match ($op) {
            'somar'       => $x + $y,
            'subtrair'    => $x - $y,
            'multiplicar' => $x * $y,
            'dividir'     => $x / $y,
        };
    }
}

Quando dá errado

Warning: Undefined array key "a"

Você escreveu $a = $_POST['a']; sem o ?? e abriu a página pela primeira vez (um GET, sem formulário enviado):

$ curl -s localhost:8000/
<br />
<b>Warning</b>:  Undefined array key "a" in <b>/home/ana/calculadora/index.php</b> on line <b>2</b><br />
<br />
<b>Warning</b>:  Undefined array key "b" in <b>/home/ana/calculadora/index.php</b> on line <b>3</b><br />
Recebi  e

O que significa: "chave de array indefinida": não existe 'a' dentro de $_POST, porque nada foi enviado. Como consertar: $_POST['a'] ?? '', que dá um valor padrão quando a chave não existe.

Fatal error: Uncaught DivisionByZeroError: Division by zero

Apareceu ao dividir por zero (etapa 3). Como consertar: confira o divisor antes da conta e transforme o caso numa mensagem para o usuário, como na etapa 4. O resto da divisão com % tem o seu próprio erro: DivisionByZeroError: Modulo by zero.

Fatal error: Uncaught UnhandledMatchError: Unhandled match case 'resto'

O match recebeu um valor que não tem braço. Como consertar: valide a operação antes (lista de permitidas) ou acrescente um braço default => …. Na calculadora preferimos validar, porque assim o usuário recebe "Operação desconhecida." em vez de um resultado inventado.

O resultado sai errado, sem erro nenhum

Por exemplo, abc + 2 dá 2. É o (float) transformando texto inválido em 0. Como consertar: is_numeric antes de converter. E se em vez de (float) você fizer a conta direto com os textos, o PHP 8.5 reclama de verdade: "abc" + 1 dá Fatal error: Uncaught TypeError: Unsupported operand types: string + int, e "5 maçãs" + 1 dá Warning: A non-numeric value encountered e o resultado 6 (veja Conversão de Tipos).

A página aparece com o código <?php à mostra

Você abriu o index.php com dois cliques (endereço file:///…). O navegador não sabe rodar PHP. Como consertar: suba o php -S localhost:8000 na pasta e abra http://localhost:8000.

Resumo

  • Um só index.php mostra o formulário (GET) e processa o envio (POST); $_SERVER['REQUEST_METHOD'] diz qual dos dois aconteceu.
  • Todo campo chega como texto e pode não chegar: $_POST['x'] ?? '' e trim.
  • Valide antes de usar: is_numeric, lista de operações permitidas, divisor diferente de zero. Junte os erros numa lista.
  • match escolhe o valor; sem braço para o valor, UnhandledMatchError.
  • number_format($n, 2, ',', '.') deixa o número no formato brasileiro.
  • Tudo que veio do usuário e volta para a página passa por htmlspecialchars, inclusive dentro de value="…".
