PHP Superglobais

As superglobais são arrays que o PHP preenche sozinho a cada requisição: o que veio na URL, o que o formulário mandou, os cookies, os arquivos enviados, dados do servidor. "Super" porque estão disponíveis em qualquer lugar, até dentro de funções, sem global. Esta página é a consulta rápida; os valores mostrados são reais, do servidor embutido (php -S) na máquina da Ana. Para aprender com calma, veja $_GET e $_POST e $_SERVER e Outras Superglobais.

Regra de segurança para a página inteira

Tudo o que vem de $_GET, $_POST, $_COOKIE, $_FILES, $_REQUEST e das chaves HTTP_* de $_SERVER foi escrito pelo visitante, que pode mandar qualquer coisa. Sempre: confira se existe (??), valide (Validar Dados), escape na saída com htmlspecialchars (XSS) e use prepared statements no banco (SQL Injection).

Todas são arrays associativos (aula): lê-se com colchetes e a chave entre aspas, e uma chave que não existe dá Warning: Undefined array key. Por isso o jeito seguro de ler é com ?? (aula):

<?php
$nome = $_GET["nome"] ?? "visitante";   // se não veio, usa "visitante"
echo "Olá, " . htmlspecialchars($nome);

E elas funcionam dentro de funções sem nenhuma declaração (as variáveis comuns não: veja Escopo):

<?php
function f() { echo $_GET["x"] ?? "sem x", " | ", $_SERVER["PHP_SELF"], "\n"; }
f();

$ php g4.php
sem x | g4.php

$_GET

Cada par nome=valor da URL vira uma chave. Os valores são sempre texto (string), mesmo que pareçam números; colchetes no nome (cores[]) fazem o PHP montar um array.

URL pedidaResultadoObservação
/tudo.php?nome=Bia&pagina=2["nome" => "Bia", "pagina" => "2"]"2" é texto: converta com (int) ou valide com filter_var.
/tudo.php[] (array vazio)$_GET["nome"] daria Undefined array key "nome"; use $_GET["nome"] ?? "".
/busca.php?q=caf%C3%A9+com+leite["q" => "café com leite"]O PHP já decodifica %C3%A9 e + (espaço). Para montar URLs, use urlencode ou http_build_query.
?cores[]=azul&cores[]=verde["cores" => ["azul", "verde"]]Vira array (o mesmo vale para $_POST). Por isso confira com is_string antes de passar a funções de texto.
/ola.php?nome=<b>Ana</b>["nome" => "<b>Ana</b>"]O visitante pode mandar HTML. Com htmlspecialchars, sai &lt;b&gt;Ana&lt;/b&gt; (inofensivo).

?>
<p>Olá, <?= htmlspecialchars($nome) ?>!</p>
<p>Método: <?= $_SERVER["REQUEST_METHOD"] ?></p>

$_POST

Os campos de um formulário com method="post". A chave é o name do campo. Os dados vão no corpo da requisição, não na URL (não aparecem no histórico nem no log do servidor).

<?php
header("Content-Type: text/plain; charset=utf-8");
echo "GET: "; var_dump($_GET);
echo "POST: "; var_dump($_POST);
echo "COOKIE: "; var_dump($_COOKIE);

$_SERVER no terminal (CLI)

Rodando php arquivo.php, não há requisição: as chaves REQUEST_* e HTTP_* não existem, e aparecem outras, como argv (os argumentos) e as variáveis de ambiente (HOME, PATH…). Veja PHP na Linha de Comando.

<?php
echo $_SERVER["argc"], "\n";
print_r($_SERVER["argv"]);
echo $_SERVER["PHP_SELF"], " | ", $_SERVER["SCRIPT_NAME"], " | ", $_SERVER["SCRIPT_FILENAME"], "\n";
echo $_SERVER["REQUEST_METHOD"] ?? "(sem REQUEST_METHOD)", "\n";
echo PHP_SAPI, "\n";

$ php cli.php ana 29
3
Array
(
    [0] => cli.php
    [1] => ana
    [2] => 29
)
cli.php | cli.php | cli.php
(sem REQUEST_METHOD)
cli

PHP_SAPI (uma constante, não uma superglobal) diz onde o PHP está rodando: cli no terminal, cli-server no php -S, apache2handler ou fpm-fcgi em servidores.

Quando dá errado: PHP_SELF no action do formulário

Um atalho antigo e perigoso, comum em tutoriais:

<form action="<?= $_SERVER["PHP_SELF"] ?>" method="post">

Como PHP_SELF inclui o PATH_INFO, que o visitante escreve na URL, alguém pode montar um link que injeta HTML na sua página:

$ curl -s "localhost:8000/self.php/%22%3E%3Cscript%3Ealert(1)%3C/script%3E"
<form action="/self.php/"><script>alert(1)</script>" method="post">

O <script> entrou no HTML: é um ataque XSS (aula). Como consertar: para enviar o formulário à própria página, deixe o action vazio (action="") ou omita-o; se precisar do valor, escape: htmlspecialchars($_SERVER["PHP_SELF"]).

$_SESSION

$_ENV

As variáveis de ambiente do sistema (como HOME). Se ela vem preenchida depende da opção variables_order do php.ini: só com a letra E. Sem php.ini o padrão é EGPCS (preenchida); os php.ini recomendados (php.ini-development e -production, usados pelas distribuições Linux) trazem GPCS (vazia):

<?php var_dump(count($_ENV)); var_dump(getenv("HOME"));

$ php env2.php
int(14)
string(9) "/home/ana"
$ php -d variables_order=GPCS env2.php
int(0)
string(9) "/home/ana"

Use getenv("NOME"): funciona nos dois casos. Variáveis de ambiente são o lugar certo para senhas de banco e chaves de API (fora do código).

$_REQUEST

Uma mistura de $_GET, $_POST e, conforme o php.ini, $_COOKIE. Quando a mesma chave existe em mais de um, vence o que vem depois na ordem (request_order, ou variables_order se ela estiver vazia): no exemplo de $_POST, o nome do POST apagou o do GET, e o cookie tema entrou junto. Nos php.ini recomendados, request_order = "GP" (sem cookies).

Evite. Você não sabe de onde o valor veio, e um link (GET) pode se passar por um formulário (POST). Use $_GET ou $_POST, explicitamente.

$GLOBALS

Um array com todas as variáveis globais do script (as criadas fora de funções), acessível de dentro das funções:

<?php
$total = 10;
function somar5() {
    $GLOBALS["total"] += 5;
}
somar5();
echo $total, "\n";

$ php g3.php
15

Desde o PHP 8.1 não dá para substituir o array inteiro:

$ cat g2.php
<?php
$GLOBALS = [];
$ php g2.php

Fatal error: $GLOBALS can only be modified using the $GLOBALS[$name] = $value syntax in /home/ana/sg/g2.php on line 2
Stack trace:
#0 {main}

Funções que mexem em variáveis globais são difíceis de entender e testar. Prefira passar valores por parâmetro e devolver com return (Escopo, Funções).

Complete para saber se o formulário foi enviado:

if ($_SERVER[""] === "POST") { … }

Complete para ler uma variável de ambiente de um jeito que funciona com qualquer variables_order:

$senha = ("DB_SENHA");

Resumo

  • $_GET (URL), $_POST (corpo do formulário), $_COOKIE, $_FILES: vêm do visitante. Leia com ??, valide, escape com htmlspecialchars.
  • Valores de $_GET/$_POST são sempre texto (ou array, com [] no nome).
  • $_SERVER["REQUEST_METHOD"], ["REQUEST_URI"], ["HTTP_…"] são as chaves mais usadas; no terminal, ["argv"].
  • $_FILES["campo"]: name, full_path, type, tmp_name, error, size. Confira error === UPLOAD_ERR_OK.
  • $_SESSION fica no servidor (depois de session_start()); $_COOKIE fica no navegador.
  • Prefira getenv a $_ENV; evite $_REQUEST e $GLOBALS.
