PHP O Servidor Embutido (php -S)

Para ver uma página PHP no navegador, alguém precisa fazer o papel de servidor web: receber o pedido do navegador, chamar o PHP e devolver o HTML. Você não precisa instalar Apache nem nginx para isso: o próprio PHP traz um servidor pequeno, ligado com um comando só, php -S. Nesta aula você vai ligá-lo, ler o que ele mostra, escolher a pasta do site, criar um roteador e desligá-lo.

Você vai aprender
  • Ligar o servidor com php -S localhost:8000 e abrir as páginas no navegador.
  • Ler a mensagem de início e o registro (log) de cada visita.
  • Escolher a pasta do site com -t.
  • Usar um script roteador para endereços "bonitos" como /contato.
  • Parar o servidor com Ctrl+C.
  • Resolver "Address in use", "Permission denied" e companhia.
  • Por que ele é só para desenvolvimento, e o que se usa em produção.

A ideia: um balcão provisório

Lembra do restaurante da aula Como o PHP Funciona? O navegador é o cliente, o servidor web é o garçom e o PHP é a cozinha. O php -S é um garçom de treinamento: atende uma mesa de cada vez, sem pressa, e anota tudo num caderno que você pode ler. Perfeito para testar em casa; péssimo para um restaurante cheio.

Você precisa do PHP instalado no seu computador para esta aula (veja Instalar no Linux ou Instalar no Windows e macOS). As caixas Experimente em modo web fazem o papel do servidor dentro do navegador, e aparecem no fim de cada seção.

Ligando o servidor

A Ana tem uma pasta site com o arquivo ola.php (o mesmo da aula Olá, Mundo). Ela entra na pasta e liga o servidor:

$ cd site
$ php -S localhost:8000
[Fri Oct 16 20:43:26 2026] PHP 8.5.8 Development Server (http://localhost:8000) started

A porta: o número da "porta de entrada" do servidor. Qualquer número de 1024 a 65535 que esteja livre serve; 8000 e 8080 são os costumeiros.

Repare que o prompt $ não voltou. O servidor fica rodando, ocupando aquele terminal, esperando visitas. É assim mesmo: deixe essa janela aberta e use outra janela (ou outra aba) do terminal para os demais comandos.

Abrindo no navegador

Abra o navegador e digite na barra de endereços:

http://localhost:8000/ola.php

A página mostra Olá, mundo!. O caminho depois da porta (/ola.php) é o nome do arquivo dentro da pasta onde você ligou o servidor. Um arquivo site/fotos/praia.jpg seria aberto em http://localhost:8000/fotos/praia.jpg.

No terminal, dá para fazer o mesmo pedido com o curl (numa outra janela do terminal, já que a primeira está ocupada pelo servidor):

$ curl localhost:8000/ola.php
Olá, mundo!

O log é a primeira coisa a olhar quando uma página "não aparece": ele diz se o pedido chegou, qual caminho foi pedido e o que o servidor respondeu. No navegador, você vai notar pedidos que não fez, como GET /favicon.ico: o navegador procura sozinho o iconezinho da aba.

Parando o servidor: Ctrl+C

Para desligar, vá à janela do servidor e aperte Ctrl+C (segure Ctrl e toque C). O terminal mostra ^C, o servidor para e o prompt volta (às vezes grudado no ^C):

$ php -S localhost:8000 -t public
[Fri Oct 16 21:01:47 2026] PHP 8.5.8 Development Server (http://localhost:8000) started
^C
$ echo $?
0                     « o servidor terminou sem erro

Fechar a janela do terminal também desliga o servidor. Depois de parado, o navegador passa a mostrar "Não é possível acessar esse site" (ou "Conexão recusada"), e o curl diz Failed to connect to localhost port 8000.

Não precisa reiniciar a cada mudança

O PHP lê o arquivo de novo a cada pedido. Mudou o código? Salve e recarregue a página (F5). Só é preciso parar e ligar de novo para trocar a pasta, a porta ou o roteador, ou depois de instalar uma extensão.

Escolhendo a pasta do site: -t

Sem nada mais, o servidor publica a pasta onde você estava quando o ligou. A opção -t (de target, "alvo", ou document root, a "raiz dos documentos") escolhe outra pasta. O script roteador

Sites modernos têm endereços "bonitos": /contato, /produtos/42, sem .php no fim. Não existe um arquivo contato na pasta; um programa decide o que mostrar para cada endereço. Esse programa se chama roteador (router), como um porteiro que encaminha cada visitante.

No php -S, você passa o roteador depois do endereço. A partir daí, todo pedido passa primeiro por ele:

<?php
// router.php — o "porteiro": decide o que fazer com cada pedido
$caminho = parse_url($_SERVER["REQUEST_URI"], PHP_URL_PATH);

if ($caminho === "/") {
    echo "<h1>Página inicial</h1>\n";
} elseif ($caminho === "/contato") {
    echo "<h1>Fale com a Ana</h1>\n";
} elseif (file_exists(__DIR__ . $caminho)) {
    return false; // arquivo de verdade (imagem, CSS): o servidor entrega como está
} else {
    http_response_code(404);
    echo "<h1>Página não encontrada</h1>\n";
}

Muita coisa aqui ainda é novidade (if, funções, return); cada uma tem a sua aula. A ideia geral, linha a linha:

LinhaO que faz
$caminho = parse_url(…, PHP_URL_PATH);Pega só o caminho do endereço pedido, sem o ?x=1 do fim.
if ($caminho === "/")Se pediram a raiz, mostra a página inicial (aula if, elseif, else).
elseif ($caminho === "/contato")Se pediram /contato, mostra a página de contato.
elseif (file_exists(__DIR__ . $caminho))Se existe um arquivo com esse nome na pasta…
return false;…devolve false: é o sinal combinado com o php -S para "entregue o arquivo como está".
http_response_code(404);Senão, responde com o código 404 e uma mensagem própria.
$ cd rotas
$ php -S localhost:8000 router.php

$ php -S 0.0.0.0:8000

No celular, você não digita 0.0.0.0: digita o endereço do computador na rede local (algo como http://192.168.0.10:8000; o comando hostname -I mostra o seu no Linux).

Quando dá errado

"Address in use": a porta já está ocupada 
$ php -S localhost:8000
[Fri Oct 16 21:02:03 2026] Failed to listen on localhost:8000 (reason: Address in use)
$ echo $?
1

O que aconteceu: "Falha ao escutar em localhost:8000 (motivo: endereço em uso)". Outro programa já está usando essa porta, quase sempre um php -S que você esqueceu ligado em outra janela ou aba do terminal.

Como resolver: procure a janela do servidor antigo e pare-o com Ctrl+C, ou use outra porta: php -S localhost:8080. No Linux, ss -ltnp | grep 8000 mostra qual programa está ocupando a porta.

"Permission denied" na porta 80 
$ php -S localhost:80
[Fri Oct 16 21:01:50 2026] Failed to listen on localhost:80 (reason: Permission denied)
$ echo $?
1

O que aconteceu: no Linux e no macOS, as portas abaixo de 1024 (como a 80, padrão dos sites) são reservadas ao administrador.

Como resolver: use uma porta alta, como 8000. Não use sudo para isso: rodar o servidor de testes como administrador é arriscado e desnecessário.

"Invalid address": faltou a porta 
$ php -S localhost
Invalid address: localhost

O que aconteceu: o -S exige endereço:porta. Sem os dois-pontos e o número, ele não sabe em que porta escutar.

Como resolver: php -S localhost:8000.

"Directory … does not exist": a pasta do -t está errada 
$ php -S localhost:8000 -t publico
Directory publico does not exist.

O que aconteceu: a pasta passada ao -t não existe (aqui, um erro de digitação: publico em vez de public). O caminho é relativo à pasta onde você está.

Como resolver: confira com ls e digite o nome certo (o Tab completa nomes de pastas).

404 em todas as páginas, ou a página errada

O que aconteceu: o servidor foi ligado na pasta errada. O caminho do endereço é sempre relativo à pasta do servidor (ou à do -t): ligado em ~, o arquivo ~/site/ola.php fica em /site/ola.php, não em /ola.php.

Como resolver: olhe o log: ele mostra o caminho pedido e o código. Pare o servidor, entre na pasta certa (cd site) e ligue de novo, ou use -t.

"Não é possível acessar esse site" no navegador

O que aconteceu: o servidor não está ligado (você apertou Ctrl+C ou fechou o terminal), ou a porta digitada é outra.

Como resolver: confira se a janela do servidor ainda mostra o started sem prompt depois, e se a porta da barra de endereços é a mesma do comando. Use http://, não https://: o servidor embutido não tem criptografia.

Por que não usar em produção

A própria documentação do PHP avisa: o servidor embutido é para desenvolvimento e testes. Ele atende um pedido de cada vez (se uma página demora, todas as outras esperam), não tem HTTPS, não tem as proteções e os ajustes de desempenho de um servidor de verdade e não foi feito para ficar exposto à internet.

Num site publicado, o trabalho é dividido entre dois programas:

PeçaExemplosPapel
Servidor webnginx, Apache, CaddyRecebe milhares de conexões ao mesmo tempo, cuida do HTTPS, entrega imagens e CSS direto do disco e passa os pedidos .php adiante.
Executor do PHPPHP-FPM (FastCGI Process Manager)Mantém vários processos do PHP prontos, cada um atendendo um pedido; o servidor web conversa com ele pelo protocolo FastCGI.

O caminho do pedido é o mesmo que você viu (navegador → servidor web → PHP → HTML de volta); só as peças são mais robustas. Nas hospedagens compartilhadas, tudo isso já vem configurado: você só envia os arquivos. Para o guia inteiro, o php -S basta.

  • O terminal fica ocupado com o log: Accepted, [200]: GET /caminho, Closing para cada pedido.

  • -t public publica só uma pasta; um router.php decide cada endereço (return false = entregar o arquivo).
  • Sem roteador, endereços inexistentes podem cair no index.php da raiz (com 200); sem index.php, dão 404.
  • Erros comuns: Address in use (porta ocupada), Permission denied (porta abaixo de 1024), Invalid address (faltou a porta).
  • Só para desenvolvimento; em produção, nginx ou Apache com PHP-FPM.
