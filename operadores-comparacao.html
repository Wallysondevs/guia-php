PHP Comparação (== e ===)

Comparar é fazer uma pergunta de "sim ou não": a nota é maior que 7? A senha digitada é a certa? O estoque acabou? Os operadores de comparação fazem essas perguntas e respondem true ou false. O PHP tem dois jeitos de perguntar "é igual?": o == e o ===. Entender a diferença entre eles é uma das lições mais importantes do PHP, porque o == tem surpresas que já causaram falhas de segurança de verdade.

Você vai aprender
  • A diferença entre == ("igual", converte os tipos) e === ("idêntico", compara também o tipo).
  • As surpresas reais do ==: "1" == "01", "10" == "1e1", null == false, senhas que começam com 0e… e o que mudou do PHP 7 para o PHP 8.
  • Os operadores de diferença: !=, <> e !==.
  • Maior e menor (<, >, <=, >=), inclusive com textos e acentos.
  • O operador nave espacial <=>.
  • A regra que evita as surpresas: use ===.

Antes, é bom ter visto Tipos de Dados e Booleanos. Os resultados aparecem com o var_dump, que mostra bool(true) ou bool(false).

A ideia: "parecido" × "idêntico"

Pense em R$ 10 em dinheiro e R$ 10 no Pix. Têm o mesmo valor? Sim. São a mesma coisa? Não: um é papel na carteira, o outro é um número no banco. Depende da pergunta: "dá para pagar um lanche de R$ 10?" (sim, com os dois) ou "é uma nota de papel?" (só um deles).

O PHP tem as duas perguntas:

  • == (dois iguais) pergunta "têm o mesmo valor?". Se os tipos forem diferentes, ele converte um deles antes de comparar. Chama-se igualdade (ou comparação "frouxa").
  • === (três iguais) pergunta "têm o mesmo valor e o mesmo tipo?". Não converte nada. Chama-se identidade (ou comparação "estrita").
Um =, dois ==, três ===

O = sozinho não compara: ele guarda um valor numa variável (veja Operadores de Atribuição). Trocar == por = é um dos erros mais comuns de quem começa; ele aparece na seção Quando dá errado.

Surpresa na lojinha: códigos com zero à esquerda

Os produtos da lojinha da Ana têm códigos de texto. O código do caderno é "7", mas o cliente digitou "007":

<?php
$codigoProduto = "7";
$codigoDigitado = "007";

$mesmoProduto = $codigoDigitado == $codigoProduto;
var_dump($mesmoProduto);

$ php codigo.php
bool(true)

Os dois são textos, mas como "parecem números", o == comparou 7 com 7. Para códigos, CEPs, telefones e CPFs, o zero à esquerda faz diferença: "007" e "7" são códigos diferentes.

Missão: troque a comparação para que "007" e "7" sejam considerados códigos diferentes. O resultado deve ser bool(false). Depois, troque "007" por "7" e confira que dá true.

<?php
$codigoProduto = "7";
$codigoDigitado = "007";

$mesmoProduto = $codigoDigitado == $codigoProduto;
var_dump($mesmoProduto);

<?php
$codigoProduto = "7";
$codigoDigitado = "007";

$mesmoProduto = $codigoDigitado === $codigoProduto;
var_dump($mesmoProduto);

Surpresa na segurança: senhas que começam com 0e

Um texto como "0e1234" parece um número em notação científica: 0 × 101234, que é zero. Qualquer outro "0e…" só com algarismos depois também vale zero. Então:

<?php
$senhaCerta = "0e5678";
$senhaDigitada = "0e1234";
var_dump($senhaDigitada == $senhaCerta);
var_dump($senhaDigitada === $senhaCerta);

$ php senha.php
bool(true)
bool(false)

Com ==, a senha errada foi aceita! Isso não é teoria: sistemas reais compararam códigos de senha (os "hashes", veja Senhas) com == e foram invadidos assim. Com ===, os textos são comparados letra por letra, e a senha errada é recusada.

Surpresa com funções: o zero que não é "falso"

Algumas funções do PHP devolvem um número ou false. A strpos ("posição no texto", da aula Funções de String) diz em que posição um pedaço aparece, contando do zero, e devolve false se não encontrar:

<?php
$nome = "Ana Souza";
var_dump(strpos($nome, "A"));
var_dump(strpos($nome, "A") == false);
var_dump(strpos($nome, "A") === false);
var_dump(strpos($nome, "Z"));

$ php strpos.php

bool(true)
bool(false)
bool(false)

O "A" está na posição 0 (a primeira). Mas 0 == false é verdadeiro, então a pergunta "não encontrou?" com == respondeu sim, errado. Com ===, só o false de verdade conta como "não encontrou". (O último bool(false) é a strpos dizendo que não há "Z" maiúsculo no nome.)

A regra: use ===

O === não tem nenhuma das surpresas acima: ele só diz true quando os dois lados são exatamente a mesma coisa, do mesmo tipo. Por isso a recomendação de quase todo guia de estilo de PHP é:

Regra de ouro

Compare com === e !==. Use == só quando você quer a conversão e sabe exatamente o que ela faz.

O preço do === é que você precisa cuidar dos tipos. O exemplo clássico são os dados de formulário: tudo o que vem do navegador chega como texto (veja $_GET e $_POST). Converta antes de comparar (veja Conversão de Tipos):

<?php
$idadeDigitada = "29";
var_dump($idadeDigitada === 29);
var_dump((int) $idadeDigitada === 29);

$ php form.php
bool(false)
bool(true)

O (int) transforma o texto "29" no número 29; depois disso, o === compara número com número. Assim a conversão fica visível no código, e não escondida dentro do ==.

E os números com vírgula?

Nem == nem === resolvem um problema dos float: 0.1 + 0.2 == 0.3 dá false, porque o computador guarda 0.1 e 0.2 com um errinho minúsculo. A aula int e float explica e mostra como comparar dinheiro.

Diferente: !=, <> e !==

Cada pergunta de igualdade tem a sua pergunta oposta:

  • != é o contrário de ==: "têm valores diferentes?" (com conversão). O <> é outra forma de escrever exatamente o mesmo.
  • !== é o contrário de ===: "não são idênticos?" (diferentes no valor ou no tipo).
<?php
$senha = "1234";
var_dump($senha != "1234");
var_dump($senha <> "1234");
var_dump($senha != 1234);
var_dump($senha !== 1234);
var_dump($senha !== "1234");

Missão final: três comparações perigosas

Missão: as três respostas abaixo estão erradas: todas mostram true, e todas deveriam ser false (a senha está errada, o código é outro e o estoque é zero, não null). Conserte as comparações para o programa mostrar bool(false) três vezes.

<?php

$senhaDigitada = "0e1234";

// 2. O código digitado é o mesmo do produto?
$codigoProduto = "100";
$codigoDigitado = "1e2";
var_dump($codigoDigitado == $codigoProduto);

// 3. O estoque está sem valor (null)?
$estoque = 0;
var_dump($estoque == null);

<?php
// 1. A senha digitada é igual à senha certa?
$senhaCerta = "0e5678";
$senhaDigitada = "0e1234";

// 2. O código digitado é o mesmo do produto?
$codigoProduto = "100";
$codigoDigitado = "1e2";

Resumo

  • == compara valores convertendo os tipos; === compara valor e tipo, sem converter.
  • O == acha iguais "1" e "01", "10" e "1e1", "0e1234" e "0e5678", null e false, 0 e null.
  • O PHP 8 consertou 0 == "a" (era true no PHP 7), mas as outras surpresas continuam.
  • Regra: use === e !==. Converta dados de formulário antes: (int) $idade === 29.
  • != e <> são o contrário de ==; !== é o contrário de ===.
  • < e > com textos: maiúsculas antes de minúsculas, acentos depois de tudo.
  • $a <=> $b devolve -1, 0 ou 1; serve para ordenar.
  • Um = só guarda, não compara.
