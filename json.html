PHP JSON

JSON é a língua que os programas usam para trocar dados. Quando um aplicativo de celular pede a lista de produtos a um site, quando o site consulta o CEP num serviço dos Correios, quando você salva as configurações de um programa: quase sempre os dados viajam em JSON. O PHP transforma qualquer array em JSON com uma função, e qualquer JSON de volta em dados com outra. Nesta aula você vai usar as duas, com as bandeiras que deixam o resultado legível, e vai aprender a não se enganar com um JSON quebrado.

Você vai aprender
  • O que é JSON e como ele se parece com os arrays do PHP.
  • json_encode: array → texto JSON, com JSON_PRETTY_PRINT e JSON_UNESCAPED_UNICODE (sem ela, ç vira ç).
  • json_decode: texto JSON → dados, como objeto ou como array (com true).
  • Descobrir que um JSON está errado: json_last_error_msg, JSON_THROW_ON_ERROR e json_validate (PHP 8.3+).
  • Guardar e ler dados num arquivo .json.

Para esta aula, você precisa conhecer arrays associativos e ler e escrever arquivos.

A ideia: uma ficha que qualquer programa entende

JSON (JavaScript Object Notation, "notação de objetos do JavaScript", pronuncia-se "jêison") nasceu no JavaScript, mas hoje toda linguagem lê e escreve JSON. É texto puro, com poucas regras. Veja a ficha de um produto da lojinha da Ana, em JSON:

{
    "nome": "Pão de mel",
    "preco": 4.5,
    "estoque": 30,
    "vegano": false,
    "sabores": ["chocolate", "doce de leite"],
    "foto": null
}

E a mesma ficha como array do PHP:

$produto = [
    'nome'    => 'Pão de mel',
    'preco'   => 4.5,
    'estoque' => 30,
    'vegano'  => false,
    'sabores' => ['chocolate', 'doce de leite'],
    'foto'    => null,
];

Transformar dados em texto para guardar ou enviar tem um nome: serializar (ou "codificar", encode). O caminho de volta é desserializar ("decodificar", decode). Daí os nomes das funções.

json_encode: do PHP para o JSON

<?php
$produto = [
    'nome'    => 'Pão de mel',
    'preco'   => 4.5,
    'estoque' => 30,
    'vegano'  => false,
    'sabores' => ['chocolate', 'doce de leite'],
    'foto'    => null,
];
echo json_encode($produto), "\n";

$ cd json
$ php enc1.php
{"nome":"Pão de mel","preco":4.5,"estoque":30,"vegano":false,"sabores":["chocolate","doce de leite"],"foto":null}

Funcionou: é JSON válido, numa linha só, sem espaços (o formato mais econômico para enviar pela rede). Mas repare no nome: Pão. Por padrão, o json_encode troca toda letra fora do inglês básico por um código de escape \uXXXX (ã é o "ã"). Qualquer programa que ler esse JSON vai entender "Pão" direitinho, mas para gente é ilegível:

$ php enc3.php      « três json_encode sem e com bandeiras
{"cidade":"São José","site":"https:\/\/loja.example\/bolos"}
{"cidade":"São José","site":"https://loja.example/bolos"}
["açúcar","maçã"]

Na última linha, açúcar e maçã viraram açúcar e maçã: o ç é ç. E as barras de endereço viraram \/. A segunda linha foi gerada com duas bandeiras (flags) que desligam esses escapes.

As bandeiras mais úteis

O segundo argumento do json_encode aceita bandeiras, combinadas com | (como as do file()):

<?php
// … o mesmo $produto …
echo json_encode($produto, JSON_PRETTY_PRINT | JSON_UNESCAPED_UNICODE), "\n";

$ php enc2.php
{
    "nome": "Pão de mel",
    "preco": 4.5,
    "estoque": 30,
    "vegano": false,
    "sabores": [
        "chocolate",
        "doce de leite"
    ],
    "foto": null
}
BandeiraTraduçãoEfeito
JSON_PRETTY_PRINT"impressão bonita"Quebra linhas e recua com 4 espaços. Ótimo para arquivos que pessoas vão ler.
JSON_UNESCAPED_UNICODE"Unicode sem escape"Mantém ã, ç, é como são (em UTF-8), em vez de ã.
JSON_UNESCAPED_SLASHES"barras sem escape"Mantém / em vez de \/.

Lista ou objeto? E outros detalhes

O PHP tem um tipo só (o array) para duas coisas que no JSON são diferentes (lista [] e objeto {}). Ele decide assim: se as chaves forem 0, 1, 2…, em ordem e sem buracos, vira lista; senão, vira objeto.

<?php
echo json_encode([10, 10.0, 0.1 + 0.2, '42', true, null]), "\n";
echo json_encode([]), "\n";
echo json_encode(['a', 'b', 'c']), "\n";
echo json_encode([1 => 'a', 2 => 'b']), "\n";
$lista = ['a', 'b', 'c'];
unset($lista[1]);
echo json_encode($lista), "\n";
echo json_encode(array_values($lista)), "\n";
echo json_encode([], JSON_FORCE_OBJECT), "\n";
echo json_encode('Ela disse "oi"'), "\n";

$ php tipos.php
[10,10,0.30000000000000004,"42",true,null]      « 10.0 virou 10; '42' continua texto
[]
["a","b","c"]                                   « chaves 0,1,2: lista
{"1":"a","2":"b"}                               « começa em 1: objeto
{"0":"a","2":"c"}                               « o unset abriu um buraco: objeto!
["a","c"]                                       « array_values renumera: lista de novo
{}
"Ela disse \"oi\""                              « aspas dentro do texto são escapadas

A quinta linha é uma armadilha comum: depois de remover um item com unset (ou filtrar com array_filter), as chaves ficam 0, 2, e quem esperava uma lista recebe um objeto. Passe por array_values antes de codificar.

E objetos de classes?

json_encode também aceita objetos: ele grava as propriedades públicas e ignora as privadas.

$ php objeto.php     « classe Produto com $nome e $preco públicos e $custo privado
{"nome":"Brigadeiro","preco":2.5}

Para escolher o que vai no JSON, a classe pode implementar a interface JsonSerializable. Você vai ver classes e interfaces no Nível 3 (Classes e Objetos, Interfaces).

$obj = json_decode($json);
var_dump($obj);

Quando o JSON está errado

JSON é rigoroso: uma vírgula a mais ou uma aspa simples e o texto inteiro deixa de ser JSON. E o pior: json_decode não mostra aviso nenhum. Ele só devolve null, em silêncio. Para saber o que houve, pergunte com json_last_error() (um número) e json_last_error_msg() (a mensagem):

<?php
$textos = [
    "{'nome': 'Ana'}",
    '{"nome": "Ana",}',
    '{"nome": "Ana"',
    '',
    'null',
];
foreach ($textos as $t) {
    $r = json_decode($t, true);
    echo str_pad($t, 18), " => ";
    var_dump($r);
    echo "   erro: ", json_last_error(), " - ", json_last_error_msg(), "\n";
}

$ php invalido.php
{'nome': 'Ana'}    => NULL                « aspas simples: proibidas no JSON
   erro: 4 - Syntax error
{"nome": "Ana",}   => NULL                « vírgula depois do último item
   erro: 4 - Syntax error
{"nome": "Ana"     => NULL                « faltou fechar a chave
   erro: 4 - Syntax error
                   => NULL                « texto vazio também não é JSON
   erro: 4 - Syntax error
null               => NULL                « este é JSON válido: o valor null!
   erro: 0 - No error

A última linha mostra o problema de confiar no null: o texto null é um JSON perfeito, cujo valor é null. Só o json_last_error() (0 = "nenhum erro") separa os dois casos. Syntax error = "erro de sintaxe": o texto não segue as regras.

Melhor: JSON_THROW_ON_ERROR

Ficar perguntando json_last_error() depois de cada chamada é fácil de esquecer. Com a bandeira JSON_THROW_ON_ERROR, um JSON inválido vira uma exceção (JsonException), que você captura com try/catch (aula Exceções):

<?php
$json = '{"nome": "Ana",}';
try {
    $dados = json_decode($json, true, flags: JSON_THROW_ON_ERROR);
} catch (JsonException $e) {
    echo "JSON inválido: ", $e->getMessage(), "\n";
}
json_decode($json, true, flags: JSON_THROW_ON_ERROR)
As bandeiras são o quarto argumento (o terceiro é a profundidade máxima, 512 por padrão). Com o argumento nomeado flags: você pula o terceiro. A forma sem nome é json_decode($json, true, 512, JSON_THROW_ON_ERROR).
try { … }
"Tente": se algo lá dentro lançar uma exceção, o PHP pula para o catch.
catch (JsonException $e)
"Capture" exceções do tipo JsonException; $e->getMessage() traz a mensagem.
$ php throw.php
JSON inválido: Syntax error

E sem o try, a exceção para o programa, com uma mensagem clara (o que é bem melhor do que seguir com null e quebrar dez linhas depois):

$ php throw2.php     « json_decode('{"nome": "Ana",}', true, 512, JSON_THROW_ON_ERROR);

Fatal error: Uncaught JsonException: Syntax error in /home/ana/json/throw2.php:2
Stack trace:
#0 /home/ana/json/throw2.php(2): json_decode('{"nome": "Ana",...', true, 512, 4194304)
#1 {main}
  thrown in /home/ana/json/throw2.php on line 2

(O 4194304 no rastro é o valor numérico da bandeira JSON_THROW_ON_ERROR.) A mesma bandeira funciona no json_encode.

Só conferir: json_validate PHP 8.3+

Quando você só quer saber se o texto é JSON válido, sem usar os dados, json_validate responde true ou false, gastando menos memória que o json_decode:

<?php
var_dump(json_validate('{"nome": "Ana"}'));
var_dump(json_validate('{"nome": "Ana",}'));
echo json_last_error_msg(), "\n";

$ php validate.php
bool(true)
bool(false)
Syntax error

Em versões antigas (antes do 8.3), use json_decode e confira json_last_error() === JSON_ERROR_NONE.

Erro no json_encode: texto que não é UTF-8

O JSON exige UTF-8. Se uma string veio de um arquivo antigo, gravado em outra codificação (Latin-1, comum em sistemas do Windows), o json_encode falha:

<?php
$ruim = "P\xE3o";      // "Pão" em Latin-1: o ã é o byte E3
var_dump(json_encode(['nome' => $ruim]));
echo json_last_error_msg(), "\n";
var_dump(json_encode(['nome' => $ruim], JSON_INVALID_UTF8_SUBSTITUTE));

$ php utf8.php
bool(false)
Malformed UTF-8 characters, possibly incorrectly encoded
string(19) "{"nome":"P�o"}"         « o byte ruim virou o caractere de substituição

"Caracteres UTF-8 malformados, possivelmente codificados de forma incorreta". O conserto de verdade é converter o texto para UTF-8 antes (mb_convert_encoding($ruim, 'UTF-8', 'ISO-8859-1'), veja mbstring).

    '{"cliente": "Caio", "itens": 3}',
    "{'cliente': 'Duda', 'itens': 1}",
];

    $p = json_decode($json, true);

<?php

    '{"cliente": "Caio", "itens": 3}',
    "{'cliente': 'Duda', 'itens': 1}",

        echo "JSON inválido: ", $e->getMessage(), "\n";

}

JSON num arquivo

Juntando com a aula de arquivos: um arquivo .json é um ótimo "banquinho de dados" para coisas pequenas (configurações, uma lista de produtos, um cache). O ciclo é sempre o mesmo: ler o arquivo e decodificar, mudar o array, codificar e gravar.

<?php
$arquivo = __DIR__ . '/produtos.json';
$produtos = [
    ['nome' => 'Bolo de cenoura', 'preco' => 35.0],
    ['nome' => 'Torta de limão', 'preco' => 48.5],
];
file_put_contents($arquivo, json_encode($produtos, JSON_PRETTY_PRINT | JSON_UNESCAPED_UNICODE));

$lidos = json_decode(file_get_contents($arquivo), true);
$lidos[] = ['nome' => 'Brigadeiro', 'preco' => 2.5];
file_put_contents($arquivo, json_encode($lidos, JSON_PRETTY_PRINT | JSON_UNESCAPED_UNICODE));

foreach (json_decode(file_get_contents($arquivo), true) as $p) {
    echo $p['nome'], ': R$ ', number_format($p['preco'], 2, ',', '.'), "\n";
}

Arquivo JSON × banco de dados

Para poucos dados, lidos e gravados por uma pessoa por vez, um arquivo JSON resolve. Quando muita gente grava ao mesmo tempo, ou os dados crescem, use um banco de dados (veja Banco de Dados: o Básico). E para enviar JSON como resposta de um site (uma API), você vai precisar do cabeçalho Content-Type: application/json; isso fica para a aula Criar uma API JSON.

Quando dá errado

json_decode devolveu NULL

O que significa: o texto não é JSON válido (aspas simples, vírgula sobrando, chave sem aspas, texto vazio porque o arquivo não foi lido…), ou o JSON era literalmente null.

Como consertar: mostre json_last_error_msg() logo depois, ou use JSON_THROW_ON_ERROR. Para achar o erro no texto, cole o JSON num validador ou confira com json_validate.

"Cannot use object of type stdClass as array" 
Fatal error: Uncaught Error: Cannot use object of type stdClass as array in /home/ana/json/dec-erro-obj.php:3

O que significa: você decodificou sem true (objeto) e tentou ler com colchetes (array).

Como consertar: json_decode($json, true), ou leia com $obj->campo. O contrário (-> num array) dá Warning: Attempt to read property "nome" on array.

"Malformed UTF-8 characters, possibly incorrectly encoded"

O que significa: o json_encode devolveu false porque alguma string não está em UTF-8.

Como consertar: converta a origem para UTF-8 com mb_convert_encoding. Como paliativo, JSON_INVALID_UTF8_SUBSTITUTE troca os bytes ruins por � (o losango com interrogação).

Esperava uma lista […] e veio um objeto {"0":…,"2":…}

O que significa: as chaves do array não são 0, 1, 2… seguidas (depois de unset ou array_filter).

Como consertar: json_encode(array_values($lista)).

Resumo

  • JSON é texto com objetos {}, listas [], textos em aspas duplas, números com ponto, true/false/null.
  • json_encode transforma arrays em JSON; use JSON_PRETTY_PRINT | JSON_UNESCAPED_UNICODE para gente ler (sem a segunda, ç vira ç).
  • json_decode($json, true) devolve arrays; sem true, objetos stdClass (lidos com ->).
  • JSON inválido não avisa: json_decode devolve null. Use JSON_THROW_ON_ERROR (ou json_last_error_msg()); para só conferir, json_validate (8.3+).
  • Arquivo JSON: file_get_contents + json_decode para ler, json_encode + file_put_contents para gravar.
  • Listas com buracos viram objetos: use array_values.
