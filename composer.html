PHP Composer

Ninguém escreve tudo do zero. Precisa registrar o que acontece na loja num arquivo de log? Gerar PDF? Enviar e-mail? Alguém já escreveu, testou e publicou esse código. O Composer é o programa que baixa essas bibliotecas (os pacotes), as dependências delas, e liga tudo ao seu projeto com o autoload. Todo projeto PHP moderno começa com ele.

Você vai aprender
  • O que o Composer faz e o que é o Packagist.
  • A criar um projeto com composer init e ler o composer.json linha por linha.
  • A instalar um pacote com composer require e a entender versões como ^3.12.
  • Para que servem o composer.lock e a pasta vendor/.
  • A diferença entre composer install e composer update.
  • O autoload PSR-4 do seu próprio código, dump-autoload e os scripts.
O Composer não roda no editor do guia

O Composer baixa pacotes da internet, e o editor do guia roda o PHP dentro do navegador, sem acesso à rede. Por isso as sessões desta aula foram feitas no terminal da Ana (com o Composer 2.10 de verdade) e aparecem como saídas. Os "Experimente" desta página treinam o que dá para treinar no navegador: ler e escrever o composer.json. Para repetir os comandos, use o seu próprio computador (veja Instalar no Linux ou no Windows e macOS).

Criando o projeto: composer init

O composer init cria o composer.json. Sem opções, ele faz perguntas uma a uma. Aqui a Ana passa todas as respostas de uma vez e usa --no-interaction ("sem perguntas"):

$ mkdir -p lojinha && cd lojinha
$ composer init --name=ana/lojinha --description="A lojinha da Ana" --author="Ana Silva <ana@exemplo.com>" --type=project --license=MIT --autoload=src/ --no-interaction
Writing ./composer.json
Generating autoload files

Include the Composer autoloader with: require 'vendor/autoload.php';
--name=ana/lojinha
O nome do pacote, sempre no formato fornecedor/projeto, em minúsculas. O "fornecedor" (vendor) é você, a sua empresa ou o seu usuário do GitHub.
--description, --author, --license
Descrição, autora e licença (MIT é uma licença livre bem simples).

O composer.json linha por linha

$ cat composer.json
{
    "name": "ana/lojinha",
    "description": "A lojinha da Ana",
    "type": "project",
    "license": "MIT",
    "autoload": {
        "psr-4": {
            "Ana\\Lojinha\\": "src/"
        }
    },
    "authors": [
        {
            "name": "Ana Silva",
            "email": "ana@exemplo.com"
        }
    ],
    "require": {}
}
ChaveO que é
"name"Nome do pacote, fornecedor/projeto. Obrigatório só para bibliotecas publicadas; em projetos, é identificação.
"description"Uma frase sobre o projeto.
"type"project (um sistema) ou library (o padrão: uma biblioteca).
"license"A licença do código.
"autoload" → "psr-4"A regra do autoload: o namespace Ana\Lojinha\ mora em src/. Em JSON, a barra invertida é escrita dobrada (\\).
"authors"Uma lista ([ ]) de autores, cada um um objeto ({ }) com nome e e-mail.
"require"A lista de compras: pacote → versões aceitas. Ainda vazia.

Outras chaves que você vai encontrar: "require-dev" (pacotes só para desenvolvimento, como o PHPUnit), "scripts" (comandos com nome, logo abaixo), "config" (configurações do Composer) e "minimum-stability" (aceitar ou não versões de teste). O arquivo é JSON puro: aspas duplas sempre, sem vírgula depois do último item, sem comentários.

Missão: este pequeno programa lê o composer.json como o Composer faria e lista as dependências. Abra a aba composer.json e acrescente, em "require", o pacote "psr/log" na versão "^3.0". Cuidado com a vírgula entre os itens. A saída deve mostrar psr/log (^3.0).

if (!json_validate($texto)) {

O que quer dizer ^3.12

Os pacotes usam versionamento semântico: MAIOR.MENOR.CORREÇÃO. Em 3.12.1, o 3 só muda quando algo deixa de ser compatível; o 12 muda quando aparecem recursos novos; o 1, quando corrigem erros. O ^ (circunflexo) quer dizer "esta versão ou qualquer uma mais nova que não quebre o meu código":

RestriçãoAceitaUso
^3.123.12.0 até antes de 4.0.0O padrão e o recomendado
~3.12.13.12.1 até antes de 3.13.0Só correções, sem recursos novos
3.12.1Exatamente essaRaro; trava o pacote
>=3.0 <3.5Um intervaloCasos especiais
^2.0 || ^3.0A série 2 ou a série 3Bibliotecas que suportam as duas (o Monolog pede assim o psr/log)
*Qualquer umaEvite: a próxima versão maior pode quebrar tudo

Para escolher a versão na hora de instalar: composer require monolog/monolog:^3.0.

Usando o pacote

A Ana cria a sua primeira classe, no namespace que o composer init sugeriu:

<?php

declare(strict_types=1);

namespace Ana\Lojinha;

use Psr\Log\LoggerInterface;

class Pedido
{
    public function __construct(private LoggerInterface $log) {}

    public function fechar(string $cliente, float $total): void
    {
        $this->log->info("Pedido fechado", ['cliente' => $cliente, 'total' => $total]);
    }
}

<?php

declare(strict_types=1);

require __DIR__ . '/vendor/autoload.php';

use Ana\Lojinha\Pedido;
use Monolog\Logger;
use Monolog\Handler\StreamHandler;

$log = new Logger('loja');
$log->pushHandler(new StreamHandler('php://stdout'));

$pedido = new Pedido($log);
$pedido->fechar('Bruno', 69.8);
$log->warning('Estoque baixo', ['produto' => 'Caneca', 'restam' => 2]);
require __DIR__ . '/vendor/autoload.php';
O único require. A partir dele, as classes do Monolog, do psr/log e as suas (Ana\Lojinha\…) carregam sozinhas.
use Monolog\Logger;
As classes do pacote têm namespace próprio (veja Namespaces). A documentação do pacote diz quais usar.
new Logger('loja')
Cria o "diário", com o nome loja.
pushHandler(new StreamHandler('php://stdout'))
Diz onde escrever: aqui, na saída do terminal. Num site, seria um arquivo, como __DIR__ . '/logs/loja.log'.
LoggerInterface
O Pedido não depende do Monolog, e sim da interface padrão de logs (PSR-3, do pacote psr/log). Qualquer biblioteca de log compatível serviria. Veja Padrões PSR.
$ php index.php
[2026-10-16T23:48:58.786901+00:00] loja.INFO: Pedido fechado {"cliente":"Bruno","total":69.8} []
[2026-10-16T23:48:58.788077+00:00] loja.WARNING: Estoque baixo {"produto":"Caneca","restam":2} []

Cada linha tem a data e hora, o nome do log, o nível (INFO, WARNING), a mensagem e os dados extras em JSON. Repare no +00:00: o horário está em UTC (no relógio da Ana eram 20:48), porque o PHP da Ana não tem fuso horário configurado. Veja Datas e Horas para ajustar o date.timezone.

O que vai para o Git

Se o projeto usa Git, a regra é:

  • composer.json e composer.lock: sim, os dois, sempre.
  • vendor/: não. Coloque /vendor/ no arquivo .gitignore. Quem baixar o projeto roda composer install.

Dependências só de desenvolvimento: --dev

Algumas ferramentas só servem para quem programa: testes automatizados, verificadores de estilo. Elas não precisam ir para o servidor. Instale com --dev:

Por exemplo, composer require --dev phpunit/phpunit. Elas vão para a seção "require-dev". No servidor, composer install --no-dev deixa essas de fora. Você vai instalar o PHPUnit de verdade em Testes com PHPUnit.

O autoload do seu código e o dump-autoload

A seção "autoload" do composer.json diz que Ana\Lojinha\ mora em src/. Foi por isso que new Pedido(…) funcionou sem require: o autoloader do Composer transformou Ana\Lojinha\Pedido em src/Pedido.php, pela regra PSR-4 explicada em Autoload e PSR-4.

  • Criou uma classe nova dentro de src/? Nada a fazer: a regra acha o arquivo.
  • Mudou a seção "autoload" (outro prefixo, outra pasta, uma seção "files")? Rode composer dump-autoload para gerar o autoloader de novo:
$ composer dump-autoload
Generating autoload files
Generated autoload files

Packagist: como escolher um pacote

O packagist.org é onde o Composer procura os pacotes. No site, você busca pelo que precisa ("pdf", "email", "uuid") e vê, para cada pacote, o nome para o composer require, as versões, as dependências e o número de downloads. Antes de instalar, confira:

  • Downloads e estrelas: pacotes muito usados têm mais gente achando e corrigindo erros.
  • Última versão: lançada há meses, não há anos. O composer show monolog/monolog mostra released : 2026-09-29, 2 weeks ago.
  • Versão do PHP exigida ("php": ">=8.1") compatível com a sua.
  • Licença compatível com o seu projeto (MIT, BSD e Apache são as mais tranquilas).
  • Quantas dependências ele traz. Cada uma é mais código de terceiros no seu projeto.

Missão final: o Bruno editou o composer.json à mão e o deixou com três erros de JSON: uma vírgula sobrando, aspas simples e uma barra invertida que não foi dobrada. Rode para ver Syntax error, abra a aba composer.json e conserte até o programa mostrar o projeto, a dependência e o autoload.

<?php
$texto = file_get_contents(__DIR__ . '/composer.json');

if (!json_validate($texto)) {
    echo "composer.json inválido: ", json_last_error_msg(), "\n";
    exit(1);
}

$composer = json_decode($texto, true);
echo "Projeto: {$composer['name']}\n";
foreach ($composer['require'] ?? [] as $pacote => $versao) {
    echo "Dependência: $pacote ($versao)\n";
}
foreach ($composer['autoload']['psr-4'] ?? [] as $prefixo => $pasta) {
    echo "Autoload: $prefixo -> $pasta\n";
}

{
    "name": 'ana/lojinha',
    "autoload": {
        "psr-4": {
            "Ana\\Lojinha\": "src/"
        }
    },
    "require": {
        "monolog/monolog": "^3.12",
    }
}

{
    "name": "ana/lojinha",
    "autoload": {
        "psr-4": {
            "Ana\\Lojinha\\": "src/"
        }
    },
    "require": {
        "monolog/monolog": "^3.12"
    }
}

Resumo

  • O Composer baixa pacotes do Packagist, com as dependências deles, para a pasta vendor/, e gera o autoload.
  • composer.json = o que você quer ("require", "autoload", "scripts"); composer.lock = o que foi instalado, versão exata. Os dois vão para o Git; o vendor/, não.
  • composer require pacote instala; ^3.12 aceita atualizações compatíveis até antes da 4.0.
  • install segue o .lock; update procura versões novas e muda o .lock.
  • Um único require __DIR__ . '/vendor/autoload.php'; carrega os pacotes e o seu código (PSR-4 em src/); dump-autoload quando mudar a seção "autoload".
  • "scripts" dá nomes a comandos: composer loja.
