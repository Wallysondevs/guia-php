PHP Ler e Escrever Arquivos

Tudo o que um programa guarda em variáveis some quando ele termina. Para lembrar de alguma coisa até a próxima vez (a lista de compras, os recados dos clientes, o registro das vendas do dia), o programa precisa gravar num arquivo. Nesta aula você vai ler e escrever arquivos de texto, criar pastas, listar e apagar arquivos, e entender as mensagens que o PHP mostra quando algo dá errado.

Você vai aprender
  • O jeito curto: file_put_contents (gravar) e file_get_contents (ler), e como acrescentar com FILE_APPEND.
  • Ler um arquivo como uma lista de linhas com file().
  • O jeito "passo a passo": fopen, fgets, fwrite e fclose, e quando ele vale a pena.
  • Perguntar se algo existe: file_exists, is_file, is_dir.
  • Pastas: mkdir, scandir, rmdir; apagar com unlink.
  • Os erros reais: arquivo inexistente, Permission denied, File exists.

Os exemplos rodam na pasta /home/ana/arq da máquina da Ana. No editor do guia, os arquivos são criados num disco de mentira, na memória do navegador: pode gravar à vontade.

A ideia: um caderno na gaveta

Um arquivo é como um caderno guardado numa gaveta. Para usar, você precisa saber o nome do caderno e em que gaveta (pasta) ele está. Aí pode ler o que está escrito, escrever por cima (apagando o que havia) ou continuar escrevendo na próxima linha em branco. O PHP tem uma função para cada uma dessas ações.

Gravar e ler de uma vez

As duas funções mais usadas fazem tudo numa linha só:

  • file_put_contents ("pôr o conteúdo no arquivo"): grava um texto num arquivo. Se o arquivo não existe, ele é criado.
  • file_get_contents ("pegar o conteúdo do arquivo"): devolve todo o texto do arquivo, como uma string.
<?php
$bytes = file_put_contents('compras.txt', "arroz\nfeijão\nleite\n");
var_dump($bytes);
echo file_get_contents('compras.txt');

Por que 20, se são 19 caracteres?

Conte: arroz (5) + feijão (6) + leite (5) + 3 quebras de linha = 19 caracteres. Mas o ã ocupa 2 bytes em UTF-8, então o arquivo tem 20 bytes. A mesma história do strlen com acentos.

Escrever por cima × acrescentar no fim

Cuidado: por padrão, file_put_contents apaga o que havia no arquivo e grava o texto novo. Para acrescentar no fim, passe a "bandeira" (flag) FILE_APPEND ("anexar ao arquivo") como terceiro argumento:

<?php
file_put_contents('compras.txt', "café\n", FILE_APPEND);
file_put_contents('compras.txt', "açúcar\n", FILE_APPEND);
echo file_get_contents('compras.txt');

$ php acrescentar.php

café              « acrescentado
açúcar            « acrescentado

E sem o FILE_APPEND:

<?php
file_put_contents('compras.txt', "pão\n");
echo file_get_contents('compras.txt');

$ php sobrescrever.php
pão               « o resto da lista sumiu: o arquivo foi reescrito do zero
Não existe "desfazer"

Quando o PHP grava por cima, o conteúdo antigo é perdido para sempre: não vai para a lixeira. Antes de testar algo com arquivos importantes, faça uma cópia (copy('dados.txt', 'dados-copia.txt');).

Missão: o programa grava a lista e depois tenta acrescentar café e açúcar, mas a lista começa do zero a cada linha. Conserte as duas últimas gravações para que a lista final tenha os cinco itens.

<?php

Ler linha por linha com file()

Muitas vezes você não quer o texto inteiro, e sim cada linha separada, para contar, filtrar ou mostrar numa lista. A função file() lê o arquivo e devolve um array, com uma linha em cada posição:

<?php
file_put_contents('compras.txt', "arroz\nfeijão\n\nleite\n");
$linhas = file('compras.txt');
var_dump($linhas);

$ php linhas.php

O jeito passo a passo: fopen, fgets, fwrite, fclose

file_get_contents e file() carregam o arquivo inteiro na memória. Para arquivos pequenos, perfeito. Para um arquivo de registro com 2 GB, o programa estouraria a memória. O jeito "clássico", herdado da linguagem C, abre o arquivo e lê ou escreve um pedaço por vez:

  1. fopen (file open, "abrir arquivo"): abre e devolve um identificador (um "marcador de página" do caderno).
  2. fgets (file get string, "pegar uma linha"): lê a próxima linha. Ou fwrite (file write, "escrever"): escreve um texto.
  3. fclose (file close, "fechar"): fecha o arquivo e libera o identificador.
<?php
$arquivo = fopen('diario.txt', 'w');
fwrite($arquivo, "16/10: vendi 3 bolos\n");
fwrite($arquivo, "17/10: vendi 5 bolos\n");
fclose($arquivo);

$arquivo = fopen('diario.txt', 'r');
$numero = 1;
while (($linha = fgets($arquivo)) !== false) {
    echo $numero . ": " . $linha;
    $numero++;
}
fclose($arquivo);
LinhaO que faz
$arquivo = fopen('diario.txt', 'w');Abre para escrever ('w' = write). Cria o arquivo ou apaga o conteúdo antigo. $arquivo guarda o identificador.
fwrite($arquivo, "…\n");Escreve o texto no ponto onde o "marcador" está, e o marcador anda para depois dele.
fclose($arquivo);Fecha. Garante que tudo foi gravado no disco.
fopen('diario.txt', 'r')Abre de novo, agora para ler ('r' = read), com o marcador no começo.
while (($linha = fgets($arquivo)) !== false)Lê uma linha e guarda em $linha; quando acabar o arquivo, fgets devolve false e o while para. Os parênteses extras fazem a atribuição acontecer antes da comparação.
echo $numero . ": " . $linha;Mostra a linha com o número. Sem \n no fim, porque a linha já traz a sua quebra.
$ php fopen.php
1: 16/10: vendi 3 bolos
2: 17/10: vendi 5 bolos
$ cat diario.txt
16/10: vendi 3 bolos
17/10: vendi 5 bolos
Por que !== false e não só while ($linha = fgets($arquivo))?

Uma linha com o texto "0" (sem quebra, a última do arquivo) é considerada "falsa" pelo PHP (veja Booleanos), e o laço pararia antes da hora. Comparar com !== false só para quando o arquivo realmente acabou.

mkdir só cria uma pasta por vez, e reclama se ela já existir:

<?php

Caminhos: relativos a quê?

Um nome como 'compras.txt' ou 'pedidos/001.txt' é um caminho relativo: o PHP o procura a partir da pasta atual do programa, que é a pasta de onde ele foi chamado, e não a pasta onde o arquivo .php está. Veja:

<?php
echo getcwd(), "\n";
echo __DIR__, "\n";
file_put_contents(__DIR__ . '/registro.txt', "ok\n");
var_dump(file_exists(__DIR__ . '/registro.txt'));

$ cd ~
$ php arq/dir.php
/home/ana             « getcwd(): a pasta atual (de onde a Ana chamou)
/home/ana/arq         « __DIR__: a pasta do arquivo dir.php
bool(true)

Se o programa tivesse gravado só 'registro.txt', o arquivo iria parar em /home/ana, e não ao lado do script. Num site, a "pasta atual" depende do servidor. Por isso, a regra é a mesma da aula include e require: para arquivos que acompanham o seu programa, monte o caminho com __DIR__ . '/nome.txt'.

Um mural de recados (modo web)

Juntando tudo: uma página com um formulário onde os clientes deixam recados, guardados num arquivo de texto, um por linha. Cada vez que alguém envia, a página acrescenta uma linha e mostra todas.

<?php
$arquivo = __DIR__ . '/recados.txt';

if ($_SERVER['REQUEST_METHOD'] === 'POST') {
    $nome = trim($_POST['nome'] ?? '');
    $recado = trim($_POST['recado'] ?? '');
    if ($nome !== '' && $recado !== '') {
        $linha = str_replace("\n", ' ', "$nome: $recado") . "\n";
        file_put_contents($arquivo, $linha, FILE_APPEND | LOCK_EX);
    }
}

$recados = file_exists($arquivo)
    ? file($arquivo, FILE_IGNORE_NEW_LINES | FILE_SKIP_EMPTY_LINES)
    : [];
?>
<h1>Mural de recados da Lojinha</h1>
<form method="post">
  <input name="nome" placeholder="Seu nome">
  <input name="recado" placeholder="Seu recado">
  <button>Enviar</button>
</form>
<ul>
<?php foreach ($recados as $r): ?>
  <li><?= htmlspecialchars($r) ?></li>
<?php endforeach; ?>
</ul>
<p><?= count($recados) ?> recado(s).</p>
TrechoPor quê
str_replace("\n", ' ', …)Um recado com várias linhas quebraria a regra "um recado por linha". Trocamos as quebras por espaços.
FILE_APPEND | LOCK_EXAcrescenta no fim e tranca o arquivo (exclusive lock) durante a gravação: se dois clientes enviarem no mesmo instante, um espera o outro, e as linhas não se misturam.
file_exists(…) ? file(…) : []Na primeira visita o arquivo ainda não existe: em vez de um Warning, começamos com uma lista vazia.
htmlspecialchars($r)O recado foi escrito por um visitante. Sem escapar, um <script> no recado rodaria no navegador de todo mundo (veja XSS).

O que significa: o fopen devolveu false (primeiro aviso), e o programa passou esse false para o fgets, que esperava um arquivo aberto (um resource). O erro de verdade é o da linha 2; o da linha 3 é consequência.

Como consertar: confira o resultado do fopen antes de usar: if ($f === false) { echo "Não consegui abrir.\n"; exit(1); }. Na aula de exceções você vai ver formas mais elegantes.

"Permission denied"

A Ana tirou a permissão de escrita de um arquivo (chmod 444, veja as permissões no Guia Bash) e tentou gravar nele:

$ chmod 444 trancado.txt
$ ls -l trancado.txt
-r--r--r-- 1 ana ana 9 out 16 20:47 trancado.txt
$ php permissao.php      « $ok = file_put_contents('trancado.txt', "novo texto\n"); var_dump($ok);

Warning: file_put_contents(trancado.txt): Failed to open stream: Permission denied in /home/ana/arq/permissao.php on line 2
bool(false)

O que significa: "permissão negada". O arquivo existe, mas o usuário que roda o PHP não pode escrever nele (ou na pasta).

Como consertar: no seu computador, ajuste as permissões (chmod u+w trancado.txt). Num servidor, o PHP roda como outro usuário (no Ubuntu/Debian, www-data), e é esse usuário que precisa poder escrever na pasta de dados. Nunca resolva com chmod 777: isso deixa qualquer um no servidor alterar os arquivos.

"mkdir(): File exists" 
Warning: mkdir(): File exists in /home/ana/arq/mkdir-erro.php on line 2

O que significa: a pasta já existe.

Como consertar: pergunte antes: if (!is_dir('pedidos')) { mkdir('pedidos'); }.

Resumo

  • file_put_contents grava (por cima!) e file_get_contents lê o arquivo inteiro. FILE_APPEND acrescenta no fim.
  • file() devolve as linhas num array; use FILE_IGNORE_NEW_LINES | FILE_SKIP_EMPTY_LINES.
  • Para arquivos grandes: fopen → fgets/fwrite → fclose, com while (($linha = fgets($f)) !== false).
  • Pergunte antes com file_exists/is_dir; crie pastas com mkdir (true para o caminho todo), liste com scandir/glob, apague com unlink/rmdir.
  • Falhas viram Warning + false: confira o retorno antes de usar.
  • Caminhos relativos partem da pasta atual; use __DIR__.
  • Texto de visitante gravado em arquivo: escape com htmlspecialchars na hora de mostrar.
