PHP $_SERVER e Outras Superglobais

Você já usou três variáveis "mágicas" que existem sozinhas em qualquer programa PHP: $_GET, $_POST e $_FILES. Elas fazem parte de uma família de nove, as superglobais. Esta aula apresenta a mais curiosa delas, $_SERVER, que conta tudo sobre o pedido que chegou (quem pediu, qual endereço, com qual navegador), e fecha com o mapa da família inteira.

Você vai aprender
  • O que é uma superglobal e por que ela funciona dentro de funções.
  • O que tem dentro de $_SERVER, com a saída real do php -S.
  • As chaves mais úteis: REQUEST_METHOD, REQUEST_URI, QUERY_STRING, SCRIPT_NAME, HTTP_HOST, HTTP_USER_AGENT, REMOTE_ADDR.
  • Quais delas o visitante pode falsificar (e o caso do PHP_SELF).
  • Como $_SERVER muda no terminal (php arquivo.php).
  • $_ENV, getenv e $GLOBALS.
  • A tabela com todas as superglobais, e onde cada uma é estudada.

A ideia: o carimbo do correio

Quando uma carta chega, além do conteúdo, o envelope traz informações: o carimbo com a data, a cidade de origem, o endereço de destino, às vezes o remetente. Ninguém escreveu isso na carta; vem "de brinde" com a entrega.

$_GET e $_POST são o conteúdo da carta. $_SERVER é o envelope: o PHP anota nele como o pedido chegou e onde ele está rodando. E, como num envelope, parte dessas anotações foi escrita pelo correio (o servidor, confiável) e parte pelo remetente (o navegador, que pode escrever o que quiser).

O que é uma superglobal

Normalmente, uma variável criada fora de uma função não existe dentro dela (veja Escopo). As superglobais são a exceção: o PHP as cria antes do seu código rodar e elas são visíveis em todo lugar, sem global:

function foiEnviado(): bool
{
    return $_SERVER['REQUEST_METHOD'] === 'POST';   // funciona: superglobal
}

Todas começam com $_ e são escritas em maiúsculas (a única exceção é $GLOBALS, sem o sublinhado). Você não pode criar novas superglobais: a família é fixa.

As chaves se dividem em três grupos:

  • Cabeçalhos que o navegador mandou: todas as que começam com HTTP_. Cada cabeçalho HTTP vira uma chave: User-Agent → HTTP_USER_AGENT, Accept-Language → HTTP_ACCEPT_LANGUAGE (maiúsculas, hífen vira sublinhado, HTTP_ na frente).

Tudo o que começa com HTTP_ foi escrito pelo navegador e pode ser qualquer coisa: o curl acima "virou" um Firefox com uma opção. Use esses valores para estatísticas e conveniências (escolher o idioma da página), nunca para segurança ("só deixa entrar se vier do Chrome"). E, ao mostrar qualquer um deles na página, htmlspecialchars (Escapar a Saída). Até o REMOTE_ADDR, que é confiável, pode ser o endereço de um proxy no meio do caminho, e não da pessoa.

$_SERVER no terminal

Quando o PHP roda no terminal (php arquivo.php, veja PHP na Linha de Comando), não existe pedido HTTP. Então não há REQUEST_METHOD nem cabeçalhos, mas aparecem os argumentos (argv, argc) e as variáveis de ambiente do sistema:

<?php
echo $_SERVER['argv'][1] ?? '-', ' ', $_SERVER['argc'], ' ', $_SERVER['SCRIPT_NAME'], ' ', $_SERVER['REQUEST_METHOD'] ?? '(sem REQUEST_METHOD)', "\n";

$ php cli.php Ana
Ana 2 cli.php (sem REQUEST_METHOD)

Por isso, num código que pode rodar dos dois jeitos, leia sempre com ?? ….

$_ENV e getenv: variáveis de ambiente

O sistema operacional guarda variáveis de ambiente: configurações como HOME (a pasta pessoal), LANG (o idioma) e, em servidores, coisas como a senha do banco de dados, para não ficarem escritas no código. O PHP pode lê-las de dois jeitos:

<?php
var_dump(count($_ENV), getenv('HOME'));

$ php env.php
int(15)
string(9) "/home/ana"

No laboratório da Ana, $_ENV veio cheio porque o PHP está sem php.ini. Nos php.ini que acompanham o PHP (e na maioria dos servidores), a configuração variables_order é "GPCS", sem o E de Environment, e $_ENV fica vazio. Por isso a forma mais segura é getenv('NOME'), que funciona nos dois casos e devolve false se a variável não existir.

$GLOBALS: todas as variáveis globais

$GLOBALS é um array com todas as variáveis criadas fora de funções. Dentro de uma função, ele dá acesso a elas pelo nome:

<?php
$loja = 'Padaria da Ana';
function nomeDaLoja(): string
{
    return $GLOBALS['loja'];
}
echo nomeDaLoja(), "\n";

$ php globals.php
Padaria da Ana

Funciona, mas cria a mesma bagunça do global (veja Escopo): a função depende de uma variável que pode ser mudada em qualquer lugar. Prefira passar o valor como parâmetro. Desde o PHP 8.1, $GLOBALS não pode mais ser substituído inteiro:

<?php
$GLOBALS = [];

$ php globals2.php

Fatal error: $GLOBALS can only be modified using the $GLOBALS[$name] = $value syntax in /home/ana/site/globals2.php on line 2
Stack trace:
#0 {main}

Quando dá errado

XSS pelo PHP_SELF 
<form action="<?= $_SERVER['PHP_SELF'] ?>" method="post">
$ curl -s "localhost:8000/self.php/%22%3E%3Cb%20style=%22color:red%22%3Ehackeado%3C/b%3E"
<form action="/self.php/"><b style="color:red">hackeado</b>" method="post">

O que aconteceu: o servidor aceita texto extra depois do nome do arquivo (/self.php/qualquer-coisa ainda roda o self.php), e esse texto entra no PHP_SELF. A aspa fechou o action e o resto virou HTML. Esse código aparece em muitos tutoriais antigos.

Como resolver: para enviar à própria página, deixe o action de fora (Formulários HTML). Se precisar do caminho, use htmlspecialchars($_SERVER['SCRIPT_NAME']).

Warning: Undefined array key "HTTP_REFERER" 
$ curl -s localhost:8000/ref.php
<br />
<b>Warning</b>:  Undefined array key "HTTP_REFERER" in <b>/home/ana/site/ref.php</b> on line <b>2</b><br />

O que aconteceu: chaves HTTP_* só existem se o navegador mandou aquele cabeçalho. O Referer não vem quando a pessoa digita o endereço, abre um favorito ou quando o navegador o esconde por privacidade. O mesmo vale para QUERY_STRING (sem ?) e REQUEST_METHOD (no terminal).

Como resolver: $_SERVER['HTTP_REFERER'] ?? ''.

Warning: Undefined global variable $_SESSION 
<?php
echo $_SESSION["usuario"];

$ curl -s localhost:8000/sess.php
<br />
<b>Warning</b>:  Undefined global variable $_SESSION in <b>/home/ana/site/sess.php</b> on line <b>2</b><br />
<br />
<b>Warning</b>:  Trying to access array offset on null in <b>/home/ana/site/sess.php</b> on line <b>2</b><br />

O que aconteceu: $_SESSION só passa a existir depois de session_start(). Sem ela, a variável não existe (primeiro aviso) e ler ["usuario"] de "nada" (null) gera o segundo.

Como resolver: chame session_start() no começo do arquivo, como em Sessões.

O código funciona no laboratório, mas $_ENV vem vazio no servidor

O que aconteceu: o variables_order do servidor não inclui o E.

Como resolver: troque $_ENV['X'] por getenv('X').

Resumo

  • Superglobais existem em todo lugar, inclusive em funções. São nove: $_GET, $_POST, $_FILES, $_COOKIE, $_SESSION, $_REQUEST, $_SERVER, $_ENV, $GLOBALS.
  • $_SERVER descreve o pedido e o servidor: REQUEST_METHOD, REQUEST_URI, QUERY_STRING, SCRIPT_NAME, REMOTE_ADDR…
  • Cada cabeçalho HTTP vira HTTP_NOME; todos podem ser falsificados e podem não existir: ?? '' e htmlspecialchars.
  • Não use PHP_SELF sem escape; para enviar à própria página, omita o action.
  • No terminal, $_SERVER não tem dados de pedido, mas tem argv/argc.
  • Para variáveis de ambiente, getenv. $GLOBALS existe, mas prefira parâmetros.
