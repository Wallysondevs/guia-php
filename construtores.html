PHP Construtores

Até agora, a Ana criava um produto vazio com new Produto() e preenchia as propriedades uma por uma. É fácil esquecer uma. O construtor resolve isso: é um método especial que roda sozinho no momento do new e recebe os dados que o objeto precisa para nascer completo. Nesta aula você também vai ver a promoção de propriedades do PHP 8.0, que faz a mesma coisa com muito menos código.

Você vai aprender
  • Escrever um construtor com __construct e passar os dados no new.
  • Dar valores padrão aos parâmetros do construtor.
  • Validar os dados e recusar um objeto inválido.
  • A promoção de propriedades no construtor (PHP 8.0).
  • Criar objetos com argumentos nomeados: new Produto(nome: "Caneca", preco: 25.90).
  • A ideia do __destruct, o método que roda quando o objeto é descartado.

O problema: objetos "pela metade"

Com propriedades sem valor inicial (como você viu em Propriedades e Métodos), basta esquecer uma atribuição para o programa quebrar mais adiante:

<?php
class Produto
{
    public string $nome;
    public float $preco;
}

$caneca = new Produto();
$caneca->nome = "Caneca";
// a Ana esqueceu o preço...

echo "{$caneca->nome}: R$ {$caneca->preco}\n";

$ php esqueceu.php

Fatal error: Uncaught Error: Typed property Produto::$preco must not be accessed before initialization in /home/ana/loja/esqueceu.php:12
Stack trace:
#0 {main}
  thrown in /home/ana/loja/esqueceu.php on line 12

O erro aparece na linha 12, longe da linha onde o preço deveria ter sido dado. Num programa grande, achar onde a Ana "esqueceu" é difícil. O ideal é que seja impossível criar um produto sem nome e sem preço.

Pense na maternidade: um bebê não sai do hospital sem certidão de nascimento com nome, data e local. O construtor é essa certidão: o objeto só "nasce" com os dados obrigatórios.

O construtor: __construct

<?php
class Produto
{
    public string $nome;
    public float $preco;
    public int $estoque;

    public function __construct(string $nome, float $preco, int $estoque)
    {
        $this->nome = $nome;
        $this->preco = $preco;
        $this->estoque = $estoque;
        echo "Produto criado: {$this->nome}\n";
    }
}

$caneca = new Produto("Caneca", 25.90, 10);
$camiseta = new Produto("Camiseta", 49.90, 4);

echo "{$caneca->nome} custa R$ {$caneca->preco} ({$caneca->estoque} em estoque)\n";

$ php construtor.php
Produto criado: Caneca
Produto criado: Camiseta
Caneca custa R$ 25.9 (10 em estoque)
public function __construct(…)
O construtor. O nome é fixo: dois sublinhados e construct ("construir"). Métodos que começam com __ são métodos mágicos: o PHP os chama sozinho em momentos especiais (veja Métodos Mágicos).
string $nome, float $preco, int $estoque
Parâmetros, como em qualquer função. São variáveis locais do construtor: somem quando ele termina.
$this->nome = $nome;
Copia o valor do parâmetro $nome para a propriedade nome do objeto. Os dois têm o mesmo nome por costume, mas são coisas diferentes: $nome é o parâmetro, $this->nome é a propriedade.
new Produto("Caneca", 25.90, 10)
Os valores entre parênteses no new vão para os parâmetros do construtor, na ordem.
: (sem tipo de retorno)
O construtor não tem tipo de retorno e não devolve nada: quem "devolve" o objeto é o new.

Repare na saída: a mensagem Produto criado apareceu duas vezes, uma em cada new. Ninguém chamou __construct diretamente: o PHP chamou sozinho. A sequência de um new é:

  1. O PHP cria um objeto novo, com as propriedades nos valores iniciais (ou não inicializadas).
  2. Chama o __construct desse objeto, passando os valores dos parênteses.
  3. Quando o construtor termina, o new entrega o objeto pronto para a variável.

Agora, esquecer o preço vira um erro na linha do new, que é exatamente onde está o problema (veja Quando dá errado).

Valores padrão

Parâmetros do construtor podem ter valor padrão, como os de qualquer função. Os opcionais ficam no fim:

<?php
class Produto
{
    public string $nome;
    public float $preco;
    public int $estoque;

    public function __construct(string $nome, float $preco, int $estoque = 0)
    {
        $this->nome = $nome;
        $this->preco = $preco;
        $this->estoque = $estoque;
    }
}

$caneca = new Produto("Caneca", 25.90, 10);
$chaveiro = new Produto("Chaveiro", 12.00);

echo "{$caneca->nome}: {$caneca->estoque}\n";
echo "{$chaveiro->nome}: {$chaveiro->estoque}\n";

$ php padrao.php
Caneca: 10
Chaveiro: 0

Validar no construtor

O construtor é o porteiro do objeto: é o lugar certo para recusar dados inválidos. Se algo está errado, ele lança uma exceção (throw) e o objeto não é criado. (Exceções têm a sua aula: Exceções.)

<?php
class Produto
{
    public string $nome;
    public float $preco;

    public function __construct(string $nome, float $preco)
    {
        if (trim($nome) === "") {
            throw new InvalidArgumentException("O nome não pode ser vazio");
        }
        if ($preco < 0) {
            throw new InvalidArgumentException("Preço negativo: $preco");
        }
        $this->nome = trim($nome);
        $this->preco = $preco;
    }
}

$caneca = new Produto("  Caneca ", 25.90);
echo "[{$caneca->nome}]\n";

try {
    $erro = new Produto("Camiseta", -5);
} catch (InvalidArgumentException $e) {
    echo "Não criei o produto: " . $e->getMessage() . "\n";
}

$outro = new Produto("", 10);

$ php validar.php
[Caneca]                                  « o construtor também limpou os espaços
Não criei o produto: Preço negativo: -5   « o try/catch tratou a exceção

Fatal error: Uncaught InvalidArgumentException: O nome não pode ser vazio in /home/ana/loja/validar.php:10
Stack trace:
#0 /home/ana/loja/validar.php(29): Produto->__construct('', 10.0)
#1 {main}
  thrown in /home/ana/loja/validar.php on line 10

Três situações: a caneca passou nas regras (e o nome foi limpo com trim); a camiseta com preço negativo foi recusada, e o try/catch tratou o problema; o produto sem nome foi recusado sem try, e o programa parou com Uncaught ("não capturada"). Nos três casos, nenhum produto inválido chegou a existir.

Promoção de propriedades no construtor PHP 8.0+

Olhe de novo o construtor da caneca. Cada dado aparece três vezes: na declaração da propriedade, no parâmetro e na atribuição $this->nome = $nome. O PHP 8.0 criou um atalho: escreva a visibilidade na frente do parâmetro, e ele vira propriedade e recebe o valor sozinho. Isso se chama promoção de propriedades no construtor (constructor property promotion):

<?php
class Produto
{
    public function __construct(
        public string $nome,
        public float $preco,
        public int $estoque = 0,
    ) {
    }
}

$caneca = new Produto("Caneca", 25.90, 10);
var_dump($caneca);

$ php promocao.php
object(Produto)#1 (3) {
  ["nome"]=>
  string(6) "Caneca"
  ["preco"]=>
  float(25.9)
  ["estoque"]=>
  int(10)
}

O resultado é idêntico ao da versão longa: o objeto tem as três propriedades com os valores certos. Compare as duas formas:

Dentro dos parênteses do construtor, a palavra public (ou protected/private, de Visibilidade) é o que "promove" o parâmetro a propriedade. Sem ela, é um parâmetro comum.
um parâmetro por linha
Costume para construtores promovidos: fica fácil de ler e de acrescentar um campo.
, (vírgula depois do último)
A "vírgula final" é permitida (PHP 8.0+) e recomendada: ao acrescentar um parâmetro, você não esquece a vírgula.
{ }
O corpo pode ficar vazio. As atribuições acontecem sozinhas, antes do corpo rodar.

Misturando: promovidos, comuns e código no corpo

Nem todo parâmetro precisa virar propriedade, e o corpo pode ter código. Aqui o número só serve para montar o código do produto:

<?php
class Produto
{
    public string $codigo;

    public function __construct(
        public string $nome,
        public float $preco,
        int $numero,
    ) {
        $this->codigo = "P-" . str_pad((string) $numero, 4, "0", STR_PAD_LEFT);
    }
}

$caneca = new Produto("Caneca", 25.90, 7);
echo "{$caneca->codigo} {$caneca->nome}\n";
var_dump(isset($caneca->numero));

$ php misto.php
P-0007 Caneca
bool(false)       « $numero não tem public: é só um parâmetro, não virou propriedade

Argumentos nomeados com construtores PHP 8.0+

Com muitos parâmetros, new Produto("Caneca", 25.90, 0, true, "Cozinha") fica difícil de ler: o que é o 0? E o true? Os argumentos nomeados (que você conheceu em Parâmetros) funcionam no new também: escreva o nome do parâmetro, dois-pontos e o valor:

<?php
class Produto
{
    public function __construct(
        public string $nome,
        public float $preco,
        public int $estoque = 0,
        public bool $ativo = true,
        public string $categoria = "Geral",
    ) {
    }
}

$a = new Produto("Caneca", 25.90, 0, true, "Cozinha");
$b = new Produto(nome: "Caneca", preco: 25.90, categoria: "Cozinha");
$c = new Produto(preco: 3.50, nome: "Adesivo");
$d = new Produto("Camiseta", 49.90, ativo: false);

echo "{$b->nome} | {$b->estoque} | {$b->categoria}\n";
echo "{$c->nome} | {$c->preco} | {$c->categoria}\n";
var_dump($d->ativo);

$ php nomeados.php
Caneca | 0 | Cozinha
Adesivo | 3.5 | Geral
bool(false)
LinhaO que mostra
$a = new Produto("Caneca", 25.90, 0, true, "Cozinha");Tudo por posição: para dar a categoria, a Ana teve que repetir os padrões 0 e true.
$b = new Produto(nome: "Caneca", preco: 25.90, categoria: "Cozinha");Com nomes, ela pula os do meio: estoque e ativo ficam no padrão.
$c = new Produto(preco: 3.50, nome: "Adesivo");Com nomes, a ordem não importa.
$d = new Produto("Camiseta", 49.90, ativo: false);Dá para misturar: primeiro os posicionais, depois os nomeados.

Os nomes são os dos parâmetros do construtor, sem o $. Com a promoção, eles coincidem com os nomes das propriedades, o que torna a leitura ainda mais clara.

__destruct: quando o objeto vai embora (só a ideia)

O contrário do construtor é o destrutor, __destruct ("destruir"). O PHP o chama sozinho quando o objeto deixa de ser usado: quando nenhuma variável aponta mais para ele, ou no fim do script.

<?php
class Conexao
{
    public function __construct(public string $nome)
    {
        echo "Abrindo {$this->nome}\n";
    }

    public function __destruct()
    {
        echo "Fechando {$this->nome}\n";
    }
}

$a = new Conexao("banco");
$b = new Conexao("arquivo de log");
unset($a);
echo "Fim do script\n";

$ php destrutor.php
Abrindo banco
Abrindo arquivo de log
Fechando banco            « o unset tirou a última "etiqueta" do objeto: ele foi destruído na hora
Fim do script
Fechando arquivo de log   « o $b foi destruído quando o script terminou

Na prática, você quase nunca vai escrever um __destruct: o PHP já libera memória, fecha arquivos e conexões sozinho no fim de cada script (e cada página da web é um script curto). Ele aparece em classes que guardam um recurso que precisa ser "devolvido" (um arquivo aberto, uma trava). Basta saber que existe e quando roda.

Um sublinhado só: o construtor não roda 
<?php
class Produto
{
    public string $nome = "sem nome";

    public function _construct(string $nome)
    {
        $this->nome = $nome;
    }
}

$c = new Produto("Caneca");
echo $c->nome . "\n";

$ php construct-errado.php
sem nome

O que significa: nenhum erro, mas o nome não foi guardado. _construct (com um sublinhado) é um método comum, que ninguém chamou. E o PHP não reclama dos argumentos extras do new, porque a classe não tem construtor. O mesmo acontece com um método chamado igual à classe (function Produto(…)): era o construtor no PHP 4, e desde o PHP 8 é só um método comum.

Como consertar: são dois sublinhados: __construct.

Esquecer o public na promoção

Missão: escreva a classe Cliente com um construtor promovido com três propriedades públicas: nome (texto), email (texto) e cidade (texto, com padrão "Recife"). Resumo

  • O construtor __construct (dois sublinhados) roda sozinho a cada new e recebe os argumentos dos parênteses.
  • Use-o para que todo objeto nasça completo e para validar os dados (lançando uma exceção se algo estiver errado).
  • Parâmetros podem ter valor padrão; os opcionais ficam no fim.
  • Promoção (8.0+): public tipo $nome nos parênteses do construtor declara a propriedade e guarda o valor. É o padrão no PHP moderno.
  • Argumentos nomeados: new Produto(nome: "Caneca", preco: 25.90); pule opcionais e esqueça a ordem. Posicionais sempre antes dos nomeados.
  • __destruct roda quando o objeto é descartado; raramente é necessário.
