PHP Formatar Números

Para o PHP, mil duzentos e trinta e quatro reais e cinquenta centavos é 1234.5: ponto decimal, sem separador de milhar. Para um brasileiro, é R$ 1.234,50. Esta aula mostra como fazer essa "tradução" na hora de mostrar o número, e como arredondar do jeito certo.

Você vai aprender
  • number_format com 1, 2 e 4 argumentos, e o formato brasileiro 1.234,56.
  • Mostrar dinheiro: "R$ " . number_format(…).
  • Arredondar: round, ceil, floor, e por que o printf às vezes arredonda diferente.
  • A regra de ouro: calcule com números, formate só no fim.
  • Converter "1.234,56" (digitado por um brasileiro) de volta para número.
  • O NumberFormatter da extensão intl, e quando ele está disponível.

A ideia: o número e a "roupa" do número

Pense no valor guardado no caixa da lojinha da Ana: é um número, e o PHP faz contas com ele. Quando o valor vai para a etiqueta de preço, ele ganha uma "roupa": o R$, a vírgula, o ponto do milhar. A roupa é só para ser lida por pessoas. Ninguém faz conta com a etiqueta.

Em PHP é igual: o número continua 1234.5 (um float; veja int e float), e number_format produz um texto vestido para o leitor.

number_format

<?php
$valor = 1234.567;
echo number_format($valor), "\n";
echo number_format($valor, 2), "\n";
echo number_format($valor, 2, ",", "."), "\n";

$ php formatar.php

Missão: o caixa da Ana tem $total = 1234.5. Mostre R$ 1.234,50, juntando o texto "R$ " com o number_format no formato brasileiro.

<?php
$total = 1234.5;

$total = 1234.5;

Dinheiro: "R$ " . number_format(…)

O number_format não coloca o símbolo da moeda: você concatena. A lojinha da Ana calcula o total de uma compra e mostra o recibo:

<?php
$maca = 3 * 4.5;
$uva = 2 * 7.9;
$total = $maca + $uva;
echo "Maçã:  R$ " . number_format($maca, 2, ",", "."), "\n";
echo "Uva:   R$ " . number_format($uva, 2, ",", "."), "\n";
echo "Total: R$ " . number_format($total, 2, ",", "."), "\n";

$ php recibo.php
Maçã:  R$ 13,50
Uva:   R$ 15,80
Total: R$ 29,30

Repare na ordem: primeiro todas as contas com os números ($maca, $uva, $total), e só na linha do echo o número ganha a "roupa". Para não repetir number_format($x, 2, ",", ".") em todo lugar, você vai criar a sua própria função reais($x) na aula de Funções.

Não faça contas com o texto formatado 
<?php
$total = "R$ " . number_format(10, 2, ",", ".");
echo $total + 5;

$ php conta-texto.php

Stack trace:

"Tipos de operando não suportados: string + int". "R$ 10,00" é um texto, não dá para somar. Mesmo sem o R$, "1.234,50" seria lido errado (veja abaixo). Guarde o número, formate só para mostrar.

Arredondar: round, ceil e floor

O number_format já arredonda, mas devolve texto. Quando você precisa de um número arredondado (para continuar fazendo contas), use estas funções:

<?php
echo round(3.14159, 2), "\n";
echo round(2.5), " ", round(3.5), " ", round(-2.5), "\n";
echo round(1234.567, -2), "\n";
echo ceil(4.1), " ", floor(4.9), " ", intval(4.9), "\n";
var_dump(round(2.5));

$ php arredondar.php
3.14               « round com 2 casas
3 4 -3             « o meio (.5) vai para longe do zero, como na escola
1200               « casas negativas: arredonda para a centena
5 4 4              « ceil sobe, floor desce, intval corta
float(3)           « round devolve float, mesmo sem casas

Um uso clássico do ceil: a Ana tem 47 alunos e cada van leva 15. Quantas vans? ceil(47 / 15) dá 4: não dá para alugar 3,13 vans, e 3 não bastam.

Outras formas de arredondar o meio

O round aceita um terceiro argumento com o "modo". round(2.5, 0, PHP_ROUND_HALF_EVEN) dá 2: o meio vai para o par mais próximo (o "arredondamento bancário"). No PHP 8.4+, o modo também pode ser escrito com o enum RoundingMode::HalfEven PHP 8.4+, que tem ainda RoundingMode::TowardsZero, AwayFromZero, PositiveInfinity… (enums são assunto de Enums).

Cuidado: o printf arredonda diferente

<?php
echo round(2.25, 1), "\n";
echo number_format(2.25, 1), "\n";
printf("%.1f\n", 2.25);
echo round(1.005, 2), " ", number_format(1.005, 2), " ", sprintf("%.2f", 1.005), "\n";

$ php diferenca.php
2.3
2.3
2.2                « o printf foi para baixo!
1.01 1.01 1.00     « de novo

Por quê? Números com casas decimais são guardados de forma aproximada (o famoso 0.1 + 0.2 que não dá exatamente 0.3; veja int e float). O número 1.005 na verdade está guardado como 1,00499999…, e o printf arredonda esse valor "verdadeiro". Já o round (e o number_format, que usa as mesmas regras) faz uma correção para dar o resultado que uma pessoa espera. Para dinheiro, prefira round e number_format.

Dinheiro "sério": trabalhe em centavos

Sistemas de pagamento costumam guardar valores em centavos, como inteiros: R$ 10,50 vira 1050. Inteiros não têm o problema de aproximação. Na hora de mostrar: number_format($centavos / 100, 2, ",", "."). Para cálculos com muitas casas, existe a extensão BCMath (bcadd, bcmul…), que faz contas com números em forma de texto, sem aproximação.

O caminho de volta: "1.234,56" para número

Quando um brasileiro digita um valor num formulário, ele vem como texto no formato brasileiro. Se você converter direto, o PHP lê só até onde entende:

<?php
var_dump((float) "1.234,56");
$brasileiro = "1.234,56";
$semPonto = str_replace(".", "", $brasileiro);
$comPonto = str_replace(",", ".", $semPonto);
$numero = (float) $comPonto;
var_dump($numero);

$ php voltar.php
float(1.234)          « parou na vírgula: virou "um vírgula dois três quatro"!
float(1234.56)        « certo

O (float) converte para número com casas (veja Conversão de Tipos). O caminho certo tem dois passos, nesta ordem:

  1. Tirar os pontos de milhar: "1.234,56" → "1234,56".
  2. Trocar a vírgula por ponto: "1234,56" → "1234.56". Agora o PHP entende.

Se você fizer na ordem inversa, a vírgula vira ponto e depois some junto com os outros pontos. Em código real, você ainda precisa validar o que foi digitado (e se a pessoa digitar "abc"?). Isso é assunto de Validar Dados.

NumberFormatter: a extensão intl

O PHP tem uma extensão chamada intl (de internationalization, "internacionalização") que sabe as regras de cada país: moeda, separadores, até números por extenso. A classe NumberFormatter formata direto no padrão de um idioma:

<?php
$moeda = new NumberFormatter("pt_BR", NumberFormatter::CURRENCY);
echo $moeda->formatCurrency(1234.5, "BRL"), "\n";

$decimal = new NumberFormatter("pt_BR", NumberFormatter::DECIMAL);
echo $decimal->format(1234.567), "\n";
Exemplo ilustrativo: não roda no laboratório nem no editor do guia

A extensão intl é grande (carrega os dados de todos os idiomas) e não vem no PHP do laboratório da Ana nem no editor deste guia. Por isso a saída acima não foi conferida aqui. Num servidor com intl instalada (no Ubuntu: sudo apt install php-intl), a primeira linha mostra o valor como R$ 1.234,50 (com um espaço especial, não separável, entre o R$ e o número) e a segunda, 1.234,567. No laboratório, o que aparece é isto:

$ php -m | grep intl
$ php intl.php

Fatal error: Uncaught Error: Class "NumberFormatter" not found in /home/ana/php/intl.php:2
Stack trace:
#0 {main}
  thrown in /home/ana/php/intl.php on line 2

O php -m | grep intl não mostrou nada: a extensão não está instalada. "Classe NumberFormatter não encontrada" é sempre esse o motivo.

Para um site em português, number_format resolve 99% dos casos e funciona em qualquer PHP. O NumberFormatter vale a pena quando o mesmo site atende vários países.

Quando dá errado

<?php
echo number_format("1234,5", 2, ",", "."), "\n";

$ php virgula.php

Fatal error: Uncaught TypeError: number_format(): Argument #1 ($num) must be of type int|float, string given in /home/ana/php/virgula.php:2
Stack trace:
#0 /home/ana/php/virgula.php(2): number_format('1234,5', 2, ',', '.')
#1 {main}

O que significa: o 1º argumento precisa ser um número (int ou float). Um texto como "1234.5" seria aceito (o PHP converte), mas "1234,5", com vírgula, não é um número para o PHP.

Como consertar: converta antes, como em o caminho de volta: (float) str_replace(",", ".", $valor).

O valor ficou mil vezes menor 
$ php voltar.php
float(1.234)
float(1234.56)

O que significa: um texto no formato brasileiro ("1.234,56") foi convertido direto para número. O PHP leu o ponto do milhar como ponto decimal e parou na vírgula. Nenhum aviso aparece.

Como consertar: tire os pontos e troque a vírgula por ponto antes de converter. E nunca guarde o valor formatado: guarde o número.

Unsupported operand types: string + int

O que significa: você tentou fazer conta com o resultado do number_format (que é texto). Veja o aviso na seção de dinheiro.

Como consertar: faça as contas com a variável numérica e chame number_format só no echo.

Class "NumberFormatter" not found

O que significa: a extensão intl não está instalada.

Como consertar: instale (sudo apt install php-intl no Ubuntu; veja Instalar no Linux) e confira com php -m. Ou use number_format, que é do núcleo do PHP e está sempre disponível.

Resumo

  • O número é para calcular; o texto formatado é para mostrar. Formate só no fim.
  • number_format($v, 2, ",", ".") → 1.234,50. Para dinheiro, concatene o "R$ ".
  • number_format devolve um texto: não faça contas com ele.
  • round arredonda (o meio vai para longe do zero), ceil sobe, floor desce, intval corta.
  • O printf pode arredondar diferente nos "empates"; para dinheiro, use round/number_format, ou trabalhe em centavos.
  • Texto brasileiro para número: tire os pontos, troque a vírgula por ponto, converta com (float).
  • NumberFormatter precisa da extensão intl (não disponível no laboratório nem no editor do guia).
